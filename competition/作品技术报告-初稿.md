## 2、摘要

openvela 此前不含 ESP32-P4 支持。本作品以 Route A 方式将 openvela（NuttX 内核）从零适配到
ESP32-P4X-Function-EV-Board，完成芯片层、板级、驱动三级移植，并在 8 个外设域完成真机验收：
MIPI-DSI 屏点亮 framebuffer 与 LVGL、GT911 触摸、SC2336 摄像头 300 帧 30.02fps 零序号跳变、
板载 C6 经 SDIO/ESP-Hosted 提供 WiFi 并打通 DHCP/DNS/TLS、ES8311 音频、LittleFS 数据分区与
7.9MB 完整中文字体 PSRAM 预加载。在适配完成的硬件上落地智能家居中控应用：LVGL 中控 UI、
米家设备与 Agent 工具控制闭环（LLM 真实控制摄像机）、云端 DeepSeek 大模型对话。全程 AI 结对
开发，沉淀 3 个可复用 Skill、8 份真机证据文档，并向 nuttx 贡献 2 个通用 V4L2 修复。

## 3、正文

### 3.1 绪论

**项目背景与问题定义**：智能家居中控面板需要"一块屏 + 触摸 + 摄像头 + 语音/
音频 + 云端 AI"的全栈能力。选用的 ESP32-P4X-Function-EV-Board 硬件规格适合
（RISC-V HP 双核 400MHz、768KB SRAM + PSRAM、MIPI-DSI/CSI 高速接口、内置
EMAC、板载 ESP32-C6 WiFi 协处理器），但截至 2026 年 6 月 openvela 分支尚未
合入 ESP32-P4——新芯片接入 openvela 生态是本作品要解决的核心问题；在此之上
验证"新硬件能否承载一个完整可用的智能家居中控应用"。

**技术难点**：

1. MIPI-DSI / MIPI-CSI 两类高速接口在 openvela 树内无先例可循，需从 ESP-HAL
   对接 NuttX framebuffer 与 V4L2 子系统，并处理 GDMA 与缓存一致性问题；
2. P4 无内置 WiFi，需打通 P4↔C6 双芯片 SDIO + ESP-Hosted 协议栈（控制面 RPC +
   WLAN 数据面），且旧版 C6 固件存在协议兼容缺陷；
3. Route A（custom chip + custom board）构建体系需自建芯片层 Kconfig/链接脚本
   与 40 余个 defconfig 配置矩阵；
4. 资源受限下加载 7.9MB 完整中文字体并保持 UI 流畅（PSRAM 用户堆预加载）。

**创新点**：

- **从 0 到 1 的新平台适配**：非既有板卡调参，而是芯片层起点的完整移植，
  相对已适配的 ESP32-S3 跨度为全新 CPU 复杂度、高速接口与双芯片架构；
- **probe-first 分级验收方法论**：每个外设先以独立 probe 程序验证物理链路
  （枚举成功 ≠ 数据有效 ≠ 时序达标三级证据），再接入子系统，8 个域全部
  留下可复查的真机日志证据链（`competition/` 目录）；
- **AI 结对 + Skill 沉淀**：开发方法论本身沉淀为 3 个可复用 Skill
  （板级 bring-up 流程、ESP32 构建烧录、中文提交规范）。

### 3.2 系统方案设计

**系统总体架构**：

```text
┌────────────────────── ESP32-P4X-Function-EV-Board ──────────────────────┐
│                                                                         │
│  GT911 触摸 ──I2C──┐                    ┌──MIPI-DSI──> EK79007 1024×600 │
│                     │                    │   (framebuffer → LVGL UI)     │
│  SC2336 摄像头 ─CSI─┤   ESP32-P4 (openvela / NuttX)                     │
│   (V4L2 RGB565)     │   ┌──────────────────────────────┐                │
│                     ├──>│ 芯片层 chips/esp32p4          │                │
│  ES8311 音频 ─I2S───┤   │ 板级 board/esp32p4/…          │                │
│   (codec+GDMA)      │   │ 智能家居应用 demos/smart_home │                │
│                     │   │  ├─ LVGL 中控 UI              │                │
│  SPI Flash ─LittleFS┘   │  ├─ 米家设备接入(miloco)       │                │
│   (/data 资源分区)      │  ├─ cAGENT 云端模型对话        │                │
│                         │  └─ 摄像头预览通路             │                │
│                         └───────┬───────────────────────┘                │
│                                 │ SDIO + ESP-Hosted                      │
│                       ESP32-C6 (WiFi 协处理器) ── WLAN ──> 云端模型 API   │
└─────────────────────────────────────────────────────────────────────────┘
```

**方案论证与选型**：

- **开发板选型**：ESP32-P4 相对 ESP32-S3 的跨度（RISC-V 双核 400MHz、MIPI
  DSI/CSI、内置 EMAC、PSRAM）正是"新硬件适配"的价值所在；官方 EV Board
  自带 C6 协处理器与 7 英寸屏接口，适合中控形态。
- **适配路线**：Route A（本仓自带 `chips/ + board/`，manifest 映射进构建树）
  对比 Route B（改 vendor 公共仓）——Route A 允许比赛期间零侵入公共仓、
  全部变更可审阅地收敛在专属仓内，获奖后再上游化。
- **端/云职责划分**：端侧负责 UI、设备控制、媒体通路与本地资源；云端负责
  大模型对话（cAGENT 经 TLS 调用模型 API）。**断网/弱网降级**：UI 与设备
  控制不依赖网络，离线模式仍可运行（smart_home 配置支持纯离线启动）。
- **网络双通路**：C6 WiFi（已真机验收）与板载以太网（方案+代码就绪）互为
  备选。

**关键模块设计**：

- **显示通路**：MIPI-DSI Host（芯片层 esp_mipi_dsi/dpi_panel）→ EK79007 面板
  DCS 初始化 → PSRAM framebuffer → NuttX `/dev/fb0` → LVGL；
- **摄像头通路**：SC2336（SCCB 控制面）→ MIPI CSI-2 → CSI Host/Bridge（ISP
  转 RGB565）→ GDMA → V4L2 多缓冲队列；
- **网络通路**：C6 分层（芯片层 SDIO 传输 + ESP-Hosted 协议 + 板级装配 +
  `net_driver_s` 注册 `wlan0`），应用层显式 DHCP/DNS/TLS；
- **米家接入（miloco）**：设备卡片、控制抽屉、摄像机 spec 拉取（带重试与
  响应缓冲调优）。

### 3.3 核心算法与技术原理

**AI 算法实现**：

- **云端模型**：应用内 cAGENT 对话代理经 C6 WiFi → TLS → **DeepSeek 云端模型
  API** 完成自然语言交互与设备控制意图解析（开放平台标准接口与 API Key
  鉴权，密钥仅存设备侧 secrets 配置、不入库）。真机已验证完整闭环：TLS
  握手、请求与响应全通，并支撑米家 Agent 工具控制（LLM→miot_device_list→
  miot_device_control→摄像机真实执行，2026-09-20 七层排障闭环达成）。
- **端侧执行**：设备控制、UI 状态机、媒体通路均在端侧实时完成，不依赖
  云端往返。

**关键机制设计**：

- **probe-first 三级证据分级**（枚举成功 ≠ 数据有效 ≠ 时序/业务达标），
  用于所有外设域的验收判定，避免"点亮即通过"的误判；
- **CSI/Bridge/GDMA 数据面调度**：多缓冲 V4L2 队列 + 完成帧统一编号
  （nuttx patch 0001）保证序号连续可审计；
- **网络栈缓冲调优**：IOB 池扩容（96→256 缓冲/16→32 链）修复多帧响应被
  整帧丢弃的问题，支撑米家 spec 大响应。

**openvela 系统能力的深度运用**：

- **图形**：NuttX framebuffer 子系统（`/dev/fb0` + `FBIO_UPDATE`）+ LVGL；
- **多媒体**：V4L2 视频子系统（RGB565 采集）、NuttX audio 子系统（ES8311
  lower-half + I2S/GDMA）、LittleFS 文件系统（MTD 分区）；
- **AI**：cAGENT 智能体框架对接云端模型；
- **对 openvela 的拓展与改进**：新增 ESP32-P4 芯片层与板级支持（Route A）、
  GT911/EK79007 两个通用驱动、ESP-Hosted SDIO 传输层；向 nuttx 公共仓
  携带 2 个通用修复（V4L2 完成帧序号、imgdata 错误码），具备上游合入价值。

**数据流与关键流程**（以摄像头预览为例）：

```text
SC2336 启流(RAW8) → CSI-2 2-lane → CSI Host/ISP(RGB565 转换)
  → Bridge → GDMA → PSRAM 帧缓冲 → V4L2 队列(video_test/UI 取帧)
```

**硬件设计与适配（新硬件适配赛道核心得分项）**：

- **是否完成全新硬件平台适配或驱动开发**：**是**。
- 芯片：Espressif ESP32-P4（RISC-V HP 双核 400MHz + LP 核，768KB SRAM，
  16MB SPI Flash + PSRAM）；开发板：ESP32-P4X-Function-EV-Board（板载
  ESP32-C6-MINI-1、7 英寸 EK79007 屏、GT911 触摸、SC2336 摄像头、ES8311
  音频、RJ45）。
- **驱动类型与验收状态**（8 域明细见 `competition/` 各证据文档）：

| 驱动/接口 | 类型 | 真机验收 |
| --- | --- | --- |
| MIPI-DSI Host + EK79007 | 芯片层+LCD 驱动 | ✅ 色条/framebuffer/LVGL |
| GT911 触摸 | input 驱动（I2C） | ✅ 单指事件链 |
| MIPI-CSI + SC2336 | 芯片层+V4L2 | ✅ 300 帧 30fps |
| ESP-Hosted over SDIO | 网络驱动（双芯片） | ✅ 至 TCP 443 |
| ES8311 | audio lower-half | ✅ codec 初始化 |
| 内置 EMAC 以太网 | 网络驱动 | 代码就绪待真机 |
| SPI Flash/LittleFS | 存储 | ✅ /data 挂载 |
| GPIO/UART/USB Console | 基础外设 | ✅ NSH |

- **适配难点与解决方案**（代表案例，完整闭环见 `competition/`）：
  1. *DSI 黑屏*：DBI 命令模式 LP 传输配置错误致面板黑屏——定位到
     cmd_mode_cfg 复位值使命令走了 HS 通道，修复后双路径视觉验收通过；
  2. *C6 SetConfig 超时*：两轮排查证伪持久化假设后，定位为旧版 C6 固件
     对缺失 `threshold`/`pmf_cfg` 嵌套消息不判空崩溃——按官方主机行为
     补齐默认消息并以先失败后通过的回归用例验证；
  3. *CSI 首帧丢失*：首帧 Bridge→GDMA 不传输——扩大 DT 过滤范围并统一
     完成帧编号（nuttx patch），300 帧日志 `sequence_gaps=0` 复测通过。

**应用/交互端设计**：LVGL 1024×600 横屏中控 UI（light-calm 浅色主题、
设备卡片、控制抽屉、
完整 MiSans 中文字体）；无移动端（米家 App 为既有生态，通过米家云对接）。

**自定义 Skill（至少 1 个，硬性要求）**：已沉淀 3 个（`.claude/skills/`）：
`openvela-board-bringup`（板级 bring-up 阶段流程/验收/quirks 方法论）、

### 3.7 总结与展望

**成果总结**：完成 openvela 对 ESP32-P4 的从零 Route A 适配（芯片层/板级/
驱动/构建体系），8 个外设域真机验收（6 域通过、以太网待真机、音频链路推进
中）；落地智能家居中控应用（LVGL UI + 米家 + 摄像头通路 + cAGENT）；沉淀
3 个 Skill、8 份证据文档、2 个 nuttx 通用 patch。

**应用前景与商业价值**：目标受众为需要低成本中控面板方案的智能家居开发者

生态；openvela 的轻量实时特性适合无风扇长时运行的墙面设备。商业模式上可
作为开发板 + 参考设计的整体方案输出，亦可上游化为 openvela 官方支持板卡
降低行业接入门槛。
