# 触摸 GT911 适配（ESP32-P4X · I2C）

| 项目 | 内容 |
| --- | --- |
| 适配对象 | Goodix GT911 电容触摸控制器（ESP32-P4X-Function-EV-Board LCD adapter） |
| 总线 | ESP32-P4 I2C0，SCL=GPIO8 / SDA=GPIO7，100 kHz，双地址 0x5d（主）/ 0x14（备用），上电自动探测 |
| 当前真机状态 | 已通过：`/dev/input0` 注册成功，`gt911_probe` 真机验证单指 `DOWN -> MOVE -> UP` 完整事件链（截至 2026-08-24） |
| 关键代码入口 | `drivers/nuttx/drivers/input/gt911.c`（通用 lower-half）、`board/esp32p4/esp32p4-function-ev-board/src/esp32p4_touch.c`（板级装配）、`app/gt911_probe/`（独立验证程序）、配置 `configs/smart_home` |

## 一、适配背景与目标

本项目以 Route A（custom chip + custom board）方式将 openvela（NuttX 内核）适配到
ESP32-P4X-Function-EV-Board。显示通路（MIPI-DSI + framebuffer + 静态 LVGL 首页）先行
通过后，触摸输入成为下一块需要打通的外设。目标：

1. 把 LCD adapter 上的 GT911 接入 NuttX input 子系统，形成标准设备节点 `/dev/input0`；
2. 在接入 LVGL 之前，用独立 probe 程序隔离验证 I2C 协议、触点解析与事件状态机；
3. 保持通用驱动与板级装配分层，便于未来复用到引出 INT/reset 的其他板卡。

硬件约束：P4X 当前使用的 LCD adapter 没有将 GT911 的 reset/INT 信号接入 SoC，因此
板级层不虚构 GPIO，而是配置 20 ms 轮询；通用驱动同时保留中断模式接口。显示分辨率
1024 x 600，最大触点 5。

## 二、适配流程

按实际阶段推进（出处：docs/硬件适配/gt911适配.md 第 3 节调用链）：

1. **I2C 装配与双地址探测**：board late initialize → `esp_bringup()` →
   `board_gt911_initialize()` → `esp_i2cbus_initialize(I2C0)`，等待 GT911 上电稳定
   100 ms 后，先按主地址 `0x5d` 调用 `gt911_register()`；读取 `0x8140` 检查
   Product ID，若返回 I2C `-EIO`，释放临时实例并尝试备用地址 `0x14`。
   只有 `-EIO` 才回退地址，避免掩盖 `-ENOMEM`、设备节点冲突等注册错误。
2. **驱动注册 /dev/input0**：Product ID 验证成功后 `touch_register()` 创建
   `/dev/input0`，启动 20 ms watchdog 轮询；轮询到期经 LPWORK 执行 `gt911_worker()` →
   `gt911_process()`：读 `0x814e` 坐标状态 → 读 `0x814f` 起始的触点记录 → 向
   `0x814e` 写 0 确认当前帧 → 解析 track ID / X / Y / size → 构造 DOWN / MOVE / UP →
   `touch_event()` 写入 touchscreen upper-half 环形缓冲区。
3. **gt911_probe 独立验证**：`app/gt911_probe` 只通过 `open("/dev/input0")` +
   `poll(POLLIN)` + `read(struct touch_sample_s)` 读取并打印 upper-half 事件，不直接
   访问 I2C，用于在 LVGL 之前隔离验证驱动。
4. **真机事件验收**：在 smart_home 固件上以 `gt911_probe 15` 完成点击/松开、按住
   滑动、四角与中心点击的单指验收（多点暂未验收）。
5. **（计划中）交给 LVGL 输入**：LVGL indev 尚未正式绑定 `/dev/input0`，属下一阶段
   工作（见第六节边界）。

## 三、关键代码与配置

| `drivers/nuttx/drivers/input/gt911.c` | 通用驱动：GT911 寄存器协议、触点追踪、事件状态机、NuttX touchscreen lower-half（已核实存在；开头注释声明支持中断或轮询 worker，I2C 事务始终在 LPWORK/线程上下文执行） |

| `app/gt911_probe/` | 独立验证程序，入口 `gt911_probe_main.c`（已核实存在） |
| `board/esp32p4/esp32p4-function-ev-board/configs/smart_home` | 触摸验收所用构建配置（已核实存在） |

### 3.2 关键寄存器与数据帧

| 寄存器 | 含义 |
| --- | --- |
| `0x8140` | Product ID，注册时用于验证 I2C 通信 |
| `0x814e` | 坐标状态；bit7 表示新帧就绪，bit[3:0] 表示触点数 |
| `0x814f` | 第一个 8 字节触点记录起始地址：byte0=track ID，byte1..2=X（小端），byte3..4=Y（小端），byte5..6=touch size（小端），byte7=reserved |

处理完一帧必须向 `0x814e` 写 0，否则控制器会保留 ready 状态，反复处理旧帧或影响
下一帧更新。已核实 `gt911.c` 中 `GT911_REG_COORD_STATUS 0x814e`、
`GT911_REG_POINT1 0x814f` 与文档一致。

### 3.3 Kconfig 与构建接入

关键配置（出处：docs/硬件适配/gt911适配.md 第 5.1 节）：

```text
CONFIG_ESP32P4_FUNCTION_EV_BOARD_GT911=y
CONFIG_ESPRESSIF_I2C0=y
CONFIG_ESPRESSIF_I2C0_MASTER_MODE=y
CONFIG_ESPRESSIF_I2C0_SCLPIN=8
CONFIG_ESPRESSIF_I2C0_SDAPIN=7
CONFIG_INPUT=y
CONFIG_INPUT_TOUCHSCREEN=y
CONFIG_INPUT_GT911=y
CONFIG_SCHED_LPWORK=y
CONFIG_LVX_USE_DEMO_CONTEST2026_031_GT911_PROBE=y
```

`CONFIG_INPUT_GT911_DIAGNOSTICS` 默认关闭（bring-up 专用，开启后每 50 次扫描打印
统计）。竞赛仓库中的驱动是唯一维护源，通过软链接脚本投影到 NuttX 工作树：

```bash
contest2026_031_niudanxianqianchong/scripts/link_nuttx_display_drivers.sh
contest2026_031_niudanxianqianchong/scripts/link_nuttx_display_drivers.sh --check
```

脚本只管理 `gt911.c/.h` 等源文件软链接，不修改 NuttX 的
`drivers/input/{Kconfig,Make.defs,CMakeLists.txt}`；构建前需确认这三个文件已包含
`CONFIG_INPUT_GT911` 和 `gt911.c` 的编译规则。构建/烧录命令：

```bash
cd ~/openvela
./build.sh contest2026_031_niudanxianqianchong/board/esp32p4/esp32p4-function-ev-board/configs/smart_home -j2

esptool --chip esp32p4 --port /dev/ttyACM0 --baud 921600 \
  write-flash -fs 16MB -fm dio -ff 80m 0x2000 nuttx/nuttx.bin
picocom -b 115200 /dev/ttyACM0
```

## 四、适配证据（真机验收）

单指日志逐字摘录（出处：docs/硬件适配/gt911适配.md 第 6.3 节"已通过的单指日志
示例"；README.md 第 5 节"真机验证命令"下引用了相同输出）：

```text
DOWN id=0 x=944 y=133 size=30x30 flags=0x59
MOVE id=0 x=944 y=133 size=30x30 flags=0x5a
UP   id=0 x=944 y=133 size=30x30 flags=0x5c
DOWN id=0 x=84  y=526 size=27x27 flags=0x59
UP   id=0 x=84  y=526 size=27x27 flags=0x5c
```

验收要点（出处：docs/硬件适配/gt911适配.md 第 1 节）：

- I2C0 与 GT911 在 100 kHz 下通信正常，本次实测地址为 `0x5d`；
- 板级按 `0x5d -> 0x14` 顺序自动探测，兼容 GT911 上电地址选择；
- 坐标随手指连续变化，范围与 1024 x 600 显示面板匹配；
- 单指 track ID 稳定为 `0`，触摸面积数据有效；
- flags 解码：`0x59`=DOWN、`0x5a`=MOVE、`0x5c`=UP，均由
  `TOUCH_{DOWN|MOVE|UP} | TOUCH_ID_VALID | TOUCH_POS_VALID | TOUCH_SIZE_VALID` 组成。

注册成功日志逐字摘录（出处：docs/硬件适配/gt911适配.md 第 7.1 节真机复测结果）：

```text
GT911 power-on wait: 100 ms before product-ID probe
GT911 probing I2C address 0x5d
GT911 product id: 39 31 31 00 (911)
GT911 registered at /dev/input0: I2C0 address=0x5d poll=20ms
P4X storage bring-up: offset=0x00800000 size=0x00100000
P4X LittleFS mounted: source=/dev/espflash mount=/data
```

**重复 MOVE 的驱动策略**：手指按住不动时，GT911 可以连续产生坐标相同的有效帧，
当前驱动会将其上报为重复 `MOVE`。这不是旧数据卡死，也不影响 LVGL 点击；判断依据
是手指移动时 X/Y 连续更新、离开后能正确产生 `UP`、再次点击产生新的 `DOWN`。bring-up
阶段暂不过滤以保留完整原始事件；如 LVGL 性能测试表明有必要，可增加位移阈值和最大
上报频率，但必须保证 `DOWN`/`UP` 永不被过滤（出处：gt911适配.md 第 4.2/7.6 节）。

## 五、遇到的问题与解决

以下均出自 docs/硬件适配/gt911适配.md 第 7 节，根因与结论如实记录。

### 5.1 GT911 Product-ID 首次读取返回 `-EIO`

部分启动在 Product-ID 读取阶段失败（此时不创建 `/dev/input0`，`gt911_probe` 报
`ENOENT`）。失败日志逐字摘录：

```text
GT911 power-on wait: 100 ms before product-ID probe
ERROR: I2C0 transfer failed: msg=0 addr=0x5d frequency=100000 \
raw=0x00000400 nack=1 timeout=0 arbitration_lost=0
ERROR: GT911 probe failed: stage=product-id-read i2c_addr=0x5d \
frequency=100000 reg=0x8140 ret=-5
ERROR: P4X GT911 initialization failed: -5
```

诊断：P4 I2C 原始错误掩码 `0x400` 明确对应 NACK（非 timeout、非 arbitration
lost）；NACK 出现在 `msg=0`（向 `0x5d` 写寄存器地址阶段）；降至 100 kHz 后可排除
400 kHz 为唯一原因；失败发生在存储挂载之前，`mount("/data")` 不是直接触发动作。
已实施修复：P4 I2C 引脚属性由逻辑或修正为位或（`INPUT_PULLUP | OUTPUT_OPEN_DRAIN`）；
总线频率从 400 kHz 收敛到 100 kHz；任务上下文打印并解码原始错误掩码；板级双静态
配置对象按 `0x5d -> 0x14` 探测且仅对 `-EIO` 回退。复测在主地址即成功（注册成功日志
见第四节）；`0x14` 回退路径尚未实测触发，仍需多次断电冷启动确认稳定性，不能将一次
成功归因于某个单独改动。

### 5.2 `/dev/input0` 存在但 Probe 无输出

现象为 `gt911_probe 30` 运行 30 秒无任何触摸行。借助可选
`CONFIG_INPUT_GT911_DIAGNOSTICS` 统计 scans/queued/ready/frames/i2c_err 及 `0x814e`
回读，证明 `scans`/`ready` 增长且 `i2c_err=0`，问题不在 I2C 总线或 LPWORK，而在
触点帧解析和事件发布路径。

### 5.3 坐标为负数、ID 错乱、size 为 0

曾出现 `MOVE id=8 x=-14077 y=8960 size=0x0 flags=0x5a`。根因：驱动曾从 `0x8150`
读取第一个触点，而 GT911 实际从 `0x814f` 开始，错一字节导致 X 低字节被当成 ID、
后续全部错位。修复为 `GT911_REG_COORD_STATUS 0x814e`、`GT911_REG_POINT1 0x814f`
（与当前 `gt911.c` 代码一致），修复后 ID 恢复为 `0`，坐标和 size 恢复合理范围。

### 5.4 触摸帧重复、下一帧更新不稳定

早期顺序是先 `touch_event()` 发布再清除 `0x814e`，把控制器 ACK 放到可能受
upper-half 处理时延影响的位置。参照 ESP32-S3 BOX-3 已验证实现收敛为
"读 `0x814e` -> 读 `0x814f` 触点 -> 写 0 到 `0x814e` -> 发布触摸事件"，并在诊断
模式下回读确认 ready bit 被清除。

### 5.5 串口持续输出 `gt911: scans=...`

根因是 bring-up 诊断开关被开启，20 ms 轮询下约每秒一条。正常验证和产品构建中
关闭（`# CONFIG_INPUT_GT911_DIAGNOSTICS is not set`），诊断代码与开关保留备查。

### 5.6 按住不动时重复打印 MOVE

见第四节"重复 MOVE 的驱动策略"，属正常现象，非坐标卡死。

## 六、当前验收状态与边界

已通过（单指，真机，smart_home 配置）：`/dev/input0` 注册、I2C 100 kHz 通信、
双地址探测框架、DOWN/MOVE/UP 完整事件链、track ID=0 稳定、size 有效。

尚未完成或待验证（出处：gt911适配.md 第 9 节、README.md 当前能力表）：

- LVGL indev 尚未正式绑定 `/dev/input0`；需在 LVGL 页面验证点击、拖动、滑动和长按；
- 需按显示方向实测确认是否需要 swap X/Y、X 镜像或 Y 镜像（坐标校准）；
- 2~5 点同时触摸的 ID 稳定性尚未真机验收；
- 休眠/唤醒、异常 I2C 恢复和长时间稳定性尚未验收；
- `0x14` 备用地址回退路径尚未制造该地址状态实测验证；
- 后续如硬件版本引出 INT/reset，可在板级 `gt911_board_s` 中实现 GPIO 回调切换为
  中断模式，不改动通用协议驱动。
