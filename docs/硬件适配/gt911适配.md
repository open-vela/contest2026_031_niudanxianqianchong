# ESP32-P4X GT911 触摸适配

## 1. 适配状态

ESP32-P4X-Function-EV-Board 已通过 LCD adapter 上的 GT911 电容触摸控制器创建
`/dev/input0`，并通过 `gt911_probe` 真机验证了单指的
`DOWN -> MOVE -> UP` 完整事件链。

当前验收结论：

- I2C0 与 GT911 通信正常，设备地址为 `0x5d`；
- 触摸设备已注册为 NuttX touchscreen upper-half 设备 `/dev/input0`；
- 坐标可随手指连续变化，范围与 `1024 x 600` 显示面板匹配；
- 单指 track ID 稳定为 `0`，触摸面积数据有效；
- `DOWN`/`MOVE`/`UP` 标志分别为 `0x59`/`0x5a`/`0x5c`；
- 驱动基础适配已通过，后续工作是 LVGL 输入接入、旋转校准和多点验证。

## 2. 硬件与板级配置

| 项目 | 当前配置 |
|---|---|
| 触摸控制器 | Goodix GT911 |
| 总线 | ESP32-P4 I2C0 |
| SCL / SDA | GPIO8 / GPIO7 |
| I2C 地址 | `0x5d` |
| I2C 频率 | 400 kHz |
| 显示分辨率 | 1024 x 600 |
| 最大触点 | 5 |
| 数据采集 | 20 ms 轮询 |
| NuttX 设备节点 | `/dev/input0` |

P4X 当前使用的 LCD adapter 没有将 GT911 的 reset/INT 信号接入 SoC，
因此板级层不虚构 GPIO，而是配置 20 ms 轮询。通用驱动同时保留了中断
模式接口，便于未来适配引出 INT/reset 的其他板卡。

## 3. 软件分层和调用链

```text
board late initialize
  -> esp_bringup()
  -> board_gt911_initialize()
  -> esp_i2cbus_initialize(I2C0)
  -> gt911_register("/dev/input0", i2c, config)
       -> 读 0x8140 检查 Product ID
       -> touch_register()
       -> 创建 /dev/input0
       -> 启动 20 ms watchdog 轮询

watchdog timeout
  -> LPWORK: gt911_worker()
  -> gt911_process()
       -> 读 0x814e 坐标状态
       -> 读 0x814f 起始的触点记录
       -> 向 0x814e 写 0，确认当前帧
       -> 解析 track ID / X / Y / size
       -> 构造 DOWN / MOVE / UP
       -> touch_event()
       -> touchscreen upper-half 写入环形缓冲区

gt911_probe / LVGL
  -> open("/dev/input0")
  -> poll(POLLIN)
  -> read(struct touch_sample_s)
```

分层职责如下：

- 通用驱动 `drivers/nuttx/drivers/input/gt911.c/.h`：负责 GT911 寄存器协议、
  触点追踪、事件状态机以及 NuttX touchscreen lower-half 实现。
- 板级装配 `board/.../src/esp32p4_touch.c`：负责 I2C0、地址、频率、
  轮询周期和 `/dev/input0` 路径。
- NuttX `touchscreen_upper.c`：负责 VFS、事件缓冲、阻塞读和 `poll()` 通知。
- `app/gt911_probe`：只读取并打印 upper-half 事件，不直接访问 I2C，
  用于在 LVGL 之前隔离验证驱动。

## 4. GT911 数据帧与事件转换

### 4.1 关键寄存器

| 寄存器 | 含义 |
|---|---|
| `0x8140` | Product ID，注册时用于验证 I2C 通信 |
| `0x814e` | 坐标状态；bit7 表示新帧就绪，bit[3:0] 表示触点数 |
| `0x814f` | 第一个 8 字节触点记录的起始地址 |

单个触点记录解析：

```text
byte 0      track ID
byte 1..2   X，小端
byte 3..4   Y，小端
byte 5..6   touch size，小端
byte 7      reserved
```

处理完一帧后必须向 `0x814e` 写入 `0`，否则控制器会继续保留
ready 状态，容易反复处理旧帧或影响下一帧更新。

### 4.2 事件状态机

驱动为 0~15 的 track ID 保存上一帧触点状态：

- 当前帧首次出现的 ID -> `TOUCH_DOWN`；
- 当前帧仍然存在的活动 ID -> `TOUCH_MOVE`；
- 上一帧活动、当前帧未出现的 ID -> `TOUCH_UP`，使用上次有效坐标。

实测 flags 解码：

| flags | 事件 | 组成 |
|---|---|---|
| `0x59` | DOWN | `TOUCH_DOWN | TOUCH_ID_VALID | TOUCH_POS_VALID | TOUCH_SIZE_VALID` |
| `0x5a` | MOVE | `TOUCH_MOVE | TOUCH_ID_VALID | TOUCH_POS_VALID | TOUCH_SIZE_VALID` |
| `0x5c` | UP | `TOUCH_UP | TOUCH_ID_VALID | TOUCH_POS_VALID | TOUCH_SIZE_VALID` |

手指按住不动时，GT911 可以连续产生坐标相同的有效帧，当前驱动会将其
上报为重复 `MOVE`。这不是旧数据卡死，也不影响 LVGL 点击；如后续需要
减少 CPU 和事件流量，可在驱动或 LVGL 输入适配层增加坐标死区/重复 MOVE 过滤。

## 5. Kconfig 和构建集成

### 5.1 关键配置

```text
CONFIG_ESP32P4_FUNCTION_EV_BOARD_GT911=y
CONFIG_ESPRESSIF_I2C0=y
CONFIG_ESPRESSIF_I2C0_MASTER_MODE=y
CONFIG_ESPRESSIF_I2C0_SCLPIN=8
CONFIG_ESPRESSIF_I2C0_SDAPIN=7
CONFIG_INPUT=y
CONFIG_INPUT_TOUCHSCREEN=y
CONFIG_INPUT_GT911=y
CONFIG_SCHED_LPWORK=y
CONFIG_LVX_USE_DEMO_CONTEST2026_031_GT911_PROBE=y
```

`CONFIG_INPUT_GT911_DIAGNOSTICS` 默认关闭。它只用于 bring-up，开启后会每
50 次扫描打印统计，并在原始帧变化或 ACK 异常时打印寄存器数据。正常
固件不应开启，避免串口刷屏并扰动调度。

### 5.2 源码与 NuttX 工作树

竞赛仓库中的驱动是唯一维护源，通过相对软链接投影到 NuttX：

```bash
cd ~/openvela
contest2026_031_niudanxianqianchong/scripts/link_nuttx_display_drivers.sh
contest2026_031_niudanxianqianchong/scripts/link_nuttx_display_drivers.sh --check
```

脚本只管理 `gt911.c/.h` 等源文件软链接，不会修改 NuttX 的
`drivers/input/{Kconfig,Make.defs,CMakeLists.txt}`。构建前需确认这三个文件已包含
`CONFIG_INPUT_GT911` 和 `gt911.c` 的编译规则。

## 7. 遇到的问题与解决方案

### 7.1 `/dev/input0` 存在，但 Probe 没有输出

**现象**

```text
nsh> gt911_probe 30
=== ESP32-P4X GT911 Touch Probe ===
reading /dev/input0 for 30 seconds; touch the panel now
gt911_probe: capture complete
```

**排查方法**

增加可选 `CONFIG_INPUT_GT911_DIAGNOSTICS`，分别统计：

- watchdog 扫描数 `scans`；
- LPWORK 投递数与错误数 `queued/queue_err`；
- ready 帧数 `ready`；
- 已发布帧数 `frames`；
- I2C 错误数 `i2c_err`；
- `0x814e` 状态、原始触点字节和清除后回读值。

诊断日志证明 `scans`/`ready` 会增长、`i2c_err=0`，因此问题不在 I2C
总线或 LPWORK，而在触点帧解析和事件发布路径。

### 7.2 坐标为负数、ID 错乱、size 为 0

**现象**

```text
MOVE id=8 x=-14077 y=8960 size=0x0 flags=0x5a
```

**根因**

驱动曾从 `0x8150` 读取第一个触点，但 GT911 的第一个记录实际从
`0x814f` 开始。错一字节后，X 低字节被当成 ID，后续 X/Y/size 全部错位。

**修复**

```c
#define GT911_REG_COORD_STATUS 0x814e
#define GT911_REG_POINT1       0x814f
```

该修复后 ID 恢复为 `0`，坐标和 size 恢复到合理范围。

### 7.3 触摸帧重复，下一帧更新不稳定

**原因**

早期处理顺序是先调用 `touch_event()` 向 upper-half 发布，然后再清除
`0x814e`。这会将控制器 ACK 放到可能受 upper-half 处理时延影响的位置。

**对比依据**

BOX-3 已验证实现使用：

```text
读 0x814e -> 读 0x814f 触点 -> 写 0 到 0x814e -> 发布触摸事件
```

P4X 驱动已同步收敛到这个顺序，并在诊断模式下回读 `0x814e`，
确认 ready bit 被清除。

### 7.4 串口持续输出 `gt911: scans=...`

**根因**

bring-up 诊断开关被开启，轮询 worker 每 50 次扫描打印一次统计。
20 ms 轮询下约等于每秒一条。

**解决**

正常验证和产品构建中关闭：

```text
# CONFIG_INPUT_GT911_DIAGNOSTICS is not set
```

保留诊断代码与 Kconfig 开关，仅在触摸无响应、ACK 异常或 I2C 错误时临时开启。

### 7.5 按住不动时重复打印 MOVE

**结论**

这是 GT911 连续有效帧与当前事件策略共同导致的正常现象，不是触摸坐标
卡死。判断依据是：手指移动时 X/Y 连续更新，离开后能正确产生 `UP`，
再次点击会产生新的 `DOWN`。

暂不在驱动中过滤，以便 bring-up 阶段保留完整原始事件。如 LVGL 性能测试表明
有必要，可增加位移阈值和最大上报频率，但必须保证 `DOWN`/`UP` 永不被过滤。

## 8. 与 ESP32-S3 BOX-3 实现的对比

| 项目 | ESP32-P4X 当前实现 | ESP32-S3 BOX-3 参考实现 |
|---|---|---|
| 驱动层次 | 通用 GT911 lower-half + P4X 板级装配 | 板级文件内集成 GT911 协议 |
| 触点起始地址 | `0x814f` | `0x814f` |
| ACK 顺序 | 读完后先清 `0x814e`，再发布 | 读完后先清 `0x814e`，再发布 |
| 采集模式 | 20 ms LPWORK 轮询 | 板级延时工作队列 |
| 地址选择 | 固定 `0x5d` | 可探测 `0x5d`/`0x24` |
| 事件 | 最多 5 点，ID + DOWN/MOVE/UP + size | 主要上报单点 DOWN/UP + pressure |

P4X 没有直接复制 BOX-3 板级驱动，而是复用已验证的寄存器和 ACK
时序，同时保持 NuttX upper-half/lower-half 分层。

## 10. 后续迭代建议

1. 先完成 LVGL `/dev/input0` 接入和四角校准，不再改动已验收的 I2C 解析。
2. 根据 LVGL 实测决定是否过滤静止 MOVE，不要在没有性能证据时提前丢弃事件。
3. 增加多点、边界坐标、快速滑动和长时间轮询测试。
4. 如后续硬件版本引出 INT/reset，在板级 `gt911_board_s` 中实现 GPIO 回调，
   切换为中断模式，不改动通用协议驱动。
