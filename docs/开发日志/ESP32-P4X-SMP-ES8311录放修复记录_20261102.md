# ESP32-P4X SMP ES8311 录放修复记录

日期：2026-11-02。基线：`contest2026` / `4d46aab`。
硬件：ESP32-P4 Function EV Board，P4 rev3.2，MAC `e8:f6:0a:e3:a6:58`。

## 结论

双核 SMP 下，重启后直接录音、播放测试音、录音文件回放及再次录音均完成，
串口保持响应，音频任务正常退出。用户最终确认“人声清楚，音量合适”。
本次验证为顺序录放；没有验证同时录放、UI 负载下的长时间采集或 KWS/VAD。

## 问题与修复

| 问题 | 证据 | 修复 |
| --- | --- | --- |
| 空音频缓冲引发整机 panic | 旧镜像 JTAG：`audio_smoke_enqueue` 访问 NULL 的 `+0x6c`，系统状态为 PANIC | 开启 codec 专用缓冲；ALLOCBUFFER 返回 0 或空指针时立即报错并回收 |
| 独立录音没有共享时钟 | RX 为 TX 的从机；只启动 RX 时无 TX 时钟，TX FIFO 空时还会停止 | 录音需要时启动 TX 时钟，P4 全双工主机关闭 `tx_stop_en` |
| 提前 FINAL 和重复 STOP | I2S 默认非 streaming，codec 又不发送 I2S START；结束后再次向已关闭的 codec MQ 发送 STOP，JTAG 落在 MQ 空 inode 访问 | 默认按持续流处理；收到 COMPLETE 后不重复 STOP，未收满数据返回错误 |
| 4096 字节 RX 无法完成 | 描述符被拆成 4032 + 64；首段完成后尾段没有预期完成事件，修改 EOF 计数/单独重启 DMA不能恢复 | 采用厂商缓存对齐单帧大小 4032；当前 P4 超限接收请求返回 `-EFBIG` |
| 单声道被当作双声道 DMA | 原 PCM 奇数样本约 99.95% 为零；10 秒录音仅约 5.6 秒，1 秒播放约 0.55 秒 | ES8311 传递声道数；RX 配置 mono 和首槽掩码，保留线上两个 I2S 时隙 |
| 人声偏小、开始有瞬态 | 用户反馈声音小；导出的 PCM 开头约半秒不稳定 | smoke 采集增益 36 dB，文件回放音量 800/1000；录音丢弃前 500 ms 后保存指定时长 |

同时复用已有音频分支的描述符预分配、锁内只操作队列、锁外启动 GDMA、
TX 续流不反复复位、RX 不在瞬时空队列时关闭等修复。活动队列检查放在同一
自旋锁内；DMA 提交前取得 APB 引用，防止完成回调先于引用增加。

## 复测命令

主线构建：

```sh
cd /home/arongw/openvela
source myenv/bin/activate
./build.sh contest2026_031_niudanxianqianchong/board/esp32p4/esp32p4-function-ev-board/configs/smart_home -j2
esptool --chip esp32p4 image-info nuttx/nuttx.bin
P4_PORT=/dev/serial/by-id/usb-Espressif_USB_JTAG_serial_debug_unit_E8:F6:0A:E3:A6:58-if00
esptool --chip esp32p4 --port "$P4_PORT" chip-id
esptool --chip esp32p4 --port "$P4_PORT" --baud 921600 write-flash -fs 16MB -fm dio -ff 80m 0x2000 nuttx/nuttx.bin
picocom -b 115200 "$P4_PORT"
```

NSH 中每条录放命令完成后，再执行下一条：

```text
ls /dev/audio
audio_smoke record 3 /data/mic_test_3s.pcm &
ls -l /data/mic_test_3s.pcm
ps
audio_smoke playfile /data/mic_test_3s.pcm &
audio_smoke play 1 &
audio_smoke record 10 /data/mic_test_10s.pcm &
ls -l /data/mic_test_10s.pcm
ps
```

3 秒和 10 秒文件应分别为 96000、320000 字节。录音启动后包含 500 ms
稳定期；应连续说话到录音完成。`playfile` 播放 RAW PCM16，不接受 WAV 头。
P4 RX 当前单帧上限为 4032 字节，应用需使用 `AUDIOIOC_GETBUFFERINFO`
返回值分配缓冲；更大的接收请求会明确报错。KWS/VAD 采集端需另行验收。

厂商单帧限制见当前 HAL `components/upper_hal_i2s/i2s_common.c` 的
`i2s_get_buf_size()` / `i2s_alloc_dma_desc()`。增益寄存器配置对照
[乐鑫 ES8311 驱动](https://github.com/espressif/esp-adf/blob/release/v2.x/components/esp_codec_dev/device/es8311/es8311.c)。
