# ESP32-P4X SMP DSI 显示与 GT911 触摸验证记录

日期：2026-10-29
状态：G3 完成，DSI 显示、GT911 触摸与 LVGL 在双核系统上运行，UI 固定在 CPU0。
关联文档：
[ESP32-P4X-SMP-LittleFS并发验证](ESP32-P4X-SMP-LittleFS并发验证_20261029.md)

## 1. 目标

在 `smp_fs`（SMP + PSRAM + Flash MTD/LittleFS）基线上接入：

- EK79007 1024×600 MIPI-DSI 面板，注册 `/dev/fb0`；
- GT911 电容触摸，注册 `/dev/input0`；
- LVGL 演示 UI，任务只允许运行在 CPU0。

## 2. 配置

新增 `configs/smp_ui`，在 `smp_fs` 基础上追加：

```text
CONFIG_ESP32P4_FUNCTION_EV_BOARD_DSI_FRAMEBUFFER=y
CONFIG_ESP32P4_FUNCTION_EV_BOARD_GT911=y
CONFIG_ESPRESSIF_I2C0=y
CONFIG_ESPRESSIF_I2C0_MASTER_MODE=y
CONFIG_ESPRESSIF_I2C0_SCLPIN=8
CONFIG_ESPRESSIF_I2C0_SDAPIN=7
CONFIG_GRAPHICS_LVGL=y
CONFIG_EXAMPLES_LVGLDEMO=y
CONFIG_LV_USE_NUTTX=y
CONFIG_LV_USE_NUTTX_TOUCHSCREEN=y
CONFIG_LV_USE_DEMO_WIDGETS=y
CONFIG_LV_FONT_MONTSERRAT_12=y
CONFIG_LV_FONT_MONTSERRAT_16=y
CONFIG_LV_FONT_MONTSERRAT_20=y
CONFIG_LV_USE_CLIB_MALLOC=y
CONFIG_LV_USE_CLIB_SPRINTF=y
CONFIG_LV_USE_CLIB_STRING=y
CONFIG_SCHED_LPWORK=y
CONFIG_SCHED_LPWORKSTACKSIZE=4096
CONFIG_NSH_JOB_CONTROL=y
```

`EXAMPLES_LVGLDEMO` 提供 `lvgldemo` 命令，默认使用 `/dev/input0` 作为触摸设备、32 KiB
栈、优先级 100。

## 3. UI 固定 CPU0

采用两层保证：

1. `CONFIG_SMP_DEFAULT_CPUSET=0x1` 来自 `smp` 基线，新建任务默认只允许 CPU0。
2. 验证时使用 `taskset 1 lvgldemo` 显式绑定，子任务继承该亲和性。

`ps` 输出中 `lvgldemo` 的 AFFINITY 为 `0x00000001`，确认只能运行在 CPU0：

```text
  PID GROUP CPU(AFFINITY)  PRI POLICY  TYPE  NPX STATE     STACK   USED  COMMAND
    9     9 ---(0x00000001) 100 RR      Task  -   Waiting   0032696 0005148 lvgldemo
```

LVGL 不是线程安全的，因此保持单任务、单核，不创建跨核渲染线程。

## 4. 板端验证

### 4.1 启动

```text
[CPU0] INFO: MIPI-DSI DPI DMA started channel=0 size=1024x600 pixel_clock_hz=52000000
[CPU0] INFO: P4X DSI backlight static=1 gpio=26
[CPU0] INFO: P4X MIPI-DSI framebuffer registered: /dev/fb0 1024x600 RGB565 buffers=2
       base=0x480001c0 bytes=2457600
[CPU0] GT911 power-on wait: 100 ms before product-ID probe
[CPU0] GT911 product id: 39 31 31 00 (911)
[CPU0] GT911 registered at /dev/input0: I2C0 address=0x5d poll=20ms
[CPU0] P4X LittleFS mounted: source=/dev/espflash mount=/data
NuttShell (NSH)
```

- 帧缓冲位于 PSRAM（`0x480001c0`，2 帧 × 1024×600×2 字节）。
- DSI 像素时钟 52 MHz，DPI DMA 已启动，无 underrun 记录。

### 4.2 UI 运行与双核并发

```text
nsh> taskset 1 lvgldemo &
nsh> ps
...
    9     9 ---(0x00000001) 100 RR  Task  -  Waiting  ... lvgldemo
```

UI 在 CPU0 运行期间，同时执行 G2 的双核 LittleFS 压测：

```text
nsh> taskset 3 smp_flash_test 8 16
smp_flash: cpu0 round 8/8 errors=0
smp_flash: cpu1 round 8/8 errors=0
smp_flash: done rounds=8 chunk=16384 errors=0 PASS
```

显示、触摸、文件系统与双核调度同时工作，无断言、无异常复位。

### 4.3 复位回归

在 CPU1 上执行 `taskset 2 reboot` 后，DSI 帧缓冲、GT911、LittleFS 全部重新初始化，
再次进入 NSH：

```text
reboot_ok = True  (CPU1 ready + framebuffer registered + GT911 registered + NuttShell)
```

## 5. 验证边界

- 本轮未进行物理触摸操作。GT911 已探测到产品 ID 并注册 `/dev/input0`，但触摸坐标
  与 LVGL 事件链路需要用户实际按压屏幕确认。
- 显示效果（颜色、方向、撕裂）需要目视确认；日志只能证明 DMA 与帧缓冲已工作。
- LVGL 演示为单任务模式，未验证多窗口或高频动画下的帧率。
- 摄像头与音频尚未接入 SMP 配置，仍属于 G4/G5。

## 6. 复现步骤

```sh
source myenv/bin/activate
./build.sh contest2026_031_niudanxianqianchong/board/esp32p4/esp32p4-function-ev-board/configs/smp_ui -j4
esptool --chip esp32p4 --port /dev/ttyACM0 --baud 921600 --after hard-reset \
  write-flash -fs 16MB -fm dio -ff 80m 0x2000 nuttx/nuttx.bin
```

串口进入 NSH 后：

```text
nsh> taskset 1 lvgldemo &
nsh> ps
nsh> taskset 3 smp_flash_test 8 16
nsh> taskset 2 reboot
```
