## 2. 修复的阻塞点

### 2.1 自定义芯片/板级 Kconfig 路径缺失

CMake 在 Kconfig 求值前不会执行 Make 的 context 规则，缺少：

- `nuttx/arch/risc-v/src/chip` → `chips/esp32p4`
- `nuttx/include/arch/chip` → `chips/esp32p4/include`
- `nuttx/arch/dummy/Kconfig` ← `chips/esp32p4/Kconfig`
- `nuttx/boards/dummy/Kconfig` ← board `Kconfig`
- `$BINDIR/arch/risc-v/src/board` → `board/esp32p4/common`

新增 `scripts/build_cmake_p4x.sh` 在配置前准备这些输入，并直接驱动 cmake
（`build.sh` 在二进制目录已存在时会跳过配置）。

### 2.2 HAL 版本与 Make 不一致

`chips/esp32p4/common/espressif/CMakeLists.txt` 默认 HAL 提交为
`0eb59f7e02a4...`，Make 为 `b90b1837cb5a...`，导致 `patches/` 下的兼容补丁
全部无法应用。已将 CMake 默认值对齐到 `b90b1837cb5ad24747deb4c895246037cc206ce5`。

### 2.3 多个链接脚本

自定义 P4 板级通过 `LD_SCRIPT` 传入 12 个脚本（ROM API、memory、sections 等），
NuttX CMake 只处理单个脚本：

```text
get_filename_component unknown component .../esp32p4.rom.eco5.libc.ld
```

补丁 `patches/nuttx/0011-cmake-multi-ld-script.patch` 改为遍历脚本列表，逐个
预处理并逐个追加 `-T`，由构建脚本自动应用。

### 2.4 mbedtls 头文件顺序

HAL 的 `components/mbedtls/port/include/mbedtls/ecp.h` 使用
`#include_next "mbedtls/private/ecp.h"`，要求 port 目录排在 mbedtls 库目录之前。
CMake 原顺序相反，且 apps 的 mbedtls 头文件先于 HAL 被搜索，造成
`MBEDTLS_ECJPAKE_C defined, but not all prerequisites` 与 `private/ecp.h` 找不到。

`hal_esp32p4.cmake` 现在把 HAL include 目录前置（`BEFORE`），并将 port 目录排在
`components/mbedtls/mbedtls/include` 之前。

### 2.5 SmartHome / cAGENT CMake 接入不完整

- `packages/cAGENT/CMakeLists.txt` 原来只是占位，未生成 `cagent` 目标。已按 Makefile
  源文件清单实现 `nuttx_add_library(cagent STATIC)`，包含 core、JSON codec、
  RAM/File/JSONL 存储、OpenAI provider、runtime/transport/TLS，并 PUBLIC 链接 mbedtls。
- `demos/smart_home/CMakeLists.txt` 缺少摄像头、miloco、LVGL 页面源码和
  cAGENT/本地 include 路径。已补齐条件源文件、图标 glob 和 `AGENT_BUILD_CONFIG_HEADER`
  定义。

### 2.6 板级 `board_app_initialize` 缺失

`src/CMakeLists.txt` 未编译 `esp32p4_appinit.c`，链接时报
`undefined reference to board_app_initialize`。已在 `CONFIG_BOARDCTL` 下加入该源文件。

### 2.7 镜像生成脚本缺失

CMake 后处理引用 `${NUTTX_DIR}/tools/espressif/espressif_mkimage.cmake`，该文件在
当前 NuttX 树中不存在。新增
`chips/esp32p4/common/espressif/espressif_mkimage.cmake`，按 Make 的
`esptool elf2image --ram-only-header` 参数从 `.config` 推导 flash 参数并生成
`nuttx.bin`。

## 3. 使用方式

```sh
cd /home/arongw/openvela
contest2026_031_niudanxianqianchong/scripts/build_cmake_p4x.sh smp_smart_home 4
```

脚本会：

1. 按需应用 `patches/nuttx/*.patch`（已应用则跳过）；
2. 准备自定义芯片/板级 Kconfig 与 symlink；
3. `source myenv/bin/activate` 并加入 riscv-none-elf 工具链路径；
4. 重新配置 `cmake_out/esp32p4-function-ev-board_<config>` 并构建。

## 4. 边界

- CMake 镜像尚未烧录验证；Make 路径仍是板端验证的主路径。
- CMake 与 Make 的编译选项存在少量差异，生成的镜像大小相差 88 字节。
- `build.sh --cmake` 仍不能直接用于自定义板卡（依赖本脚本预处理）。
- `patches/nuttx/0010`（自定义 SMP）与 `0011`（多链接脚本）都需要在干净 NuttX
  树上手工或通过脚本应用。
