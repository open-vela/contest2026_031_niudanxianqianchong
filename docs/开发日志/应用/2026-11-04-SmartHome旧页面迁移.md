# SmartHome 旧页面迁移

## 阶段一：设置与服务入口

- 删除旧设置、旧“更多”及模型、工具、MCP、Node 独立服务页，移除旧控件字段和隐藏 MCP 定时器。
- V9 工具权限直接枚举完整注册表，显示来源与可用性；聊天占用锁时立即提示忙碌，更新失败恢复开关。
- MCP 增加发现／重试、连接状态刷新与当前参数回填；后台应用配置，失败保留原桥接实例、工具白名单和自定义请求头。
- KWS 唤醒开关迁入语音服务，后台保存、失败回退；ASR/TTS 未编译时也能进入 KWS 设置。
- TTS 恢复“停止播报”操作。

MCP 地址修改仅本次运行有效；初始化仍要求有效的 `mcp_bridge.json` 及工具白名单，凭据从 `secrets.json` 读取。

验证：真实 LVGL 控件回归 20 项、真实 MCP 构造器回归、Agent ASan/UBSan 回归。测试使用服务替身，没有连接真实 MCP 服务、操作设备或烧录。

P4 对象检查在当前非 SmartHome 配置下缺少导出的 `netutils/cJSON.h`，未完成；不将主机验证视为固件或板端验收。

## 阶段二：Node 展示与剩余页面清理

- V9“设备与服务”增加 Node 节点名称、在线状态、标识和命令列表，按节点版本刷新。
- Node 端口使用严格整数校验，启停刷新实际状态，重新打开弹窗回填当前监听端口；端口日志同步修正。
- 删除旧网络、米家和安防页面源码、预览缓冲及网络线程字段，取消延迟创建旧页面。
- 旧设备页源码仅供主机回归，不再进入固件构建；产品启动只创建屏保、V9 首页、聊天和设置。设备刷新与米家版本轮询由独立 V9 模块承接。

验证：LVGL 回归 21/21（含不创建旧设备页的刷新路径）、Node-only 设置对象编译、Node 适配器对象编译，以及 UI 桥接 ASan/UBSan 回归。节点服务使用替身，不代表实际 WebSocket 接入验收。

## 阶段三：删除旧首页和设备页

- 删除旧首页 `smart_home_lvgl_home.c`、旧设备页 `smart_home_lvgl_panel.c`，公共顶栏、天气与时钟迁入 `smart_home_lvgl_shell.c`。
- 删除旧页面状态字段、导航编号、构建声明、测试专用编译开关和屏保隐藏兼容标签。
- 删除旧设备页测试，保留 V9 卡片、场景、房间、设置、扫码与摄像头回归；天气和跨日时钟改为直接验证 V9 页面。
- 保留独立的静态首页硬件诊断程序；它不属于 SmartHome 产品导航。

验证：LVGL 主机回归 21/21，UI 桥接 ASan/UBSan 通过；本次未构建或烧录 SmartHome 固件。

## 板端验证

使用 SmartHome 固件逐项验证：MCP 配置与发现／重试；工具完整列表与权限；Node 启停、端口及节点列表；ASR/TTS/KWS 配置与停止播报；首页设备控制和扫码授权。
