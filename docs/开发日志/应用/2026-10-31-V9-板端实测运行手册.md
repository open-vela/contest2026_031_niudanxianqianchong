# 2026-10-31 V9 板端实测运行手册（P01–P12）

本手册给出一条从零到回填的路径：构建 → 生成数据镜像 → 烧录 → 采集日志 → 汇总成表 → 判定像素帧动画是否准入。
命令以 openvela 根目录 `/home/arongw/openvela` 为准，配置使用 `smart_home_service_lab`（打开 MCP/Node 与 `CONFIG_SMART_HOME_V9_PERF_LOG`）。

## 0. 一键脚本（推荐）

上面的步骤都收敛在 `scripts/v9_board_measure.sh` 里，默认只打印计划、不动板子：

```sh
cd /home/arongw/openvela/worktrees/contest2026_031_niudanxianqianchong-lvgl-v9
./scripts/v9_board_measure.sh --plan                  # 只打印将执行的命令
./scripts/v9_board_measure.sh --build --image         # 构建 + 生成数据镜像
./scripts/v9_board_measure.sh --flash                 # 烧录（会覆盖板上固件）
./scripts/v9_board_measure.sh --capture 1800          # 采集 30 分钟串口日志
```

构建阶段会临时将构建树软链接指向本 worktree，脚本用 `trap` 在退出/中断时恢复运行前的实际链接目标（包括原来不存在的链接）。脚本使用绝对配置路径；固件构建或资源镜像失败均返回非零状态，拒绝以残留的旧固件判定成功。

## 1. 构建

构建树里的 `board`、`packages/demos/smart_home`、`packages/cAGENT`、`packages/cagent_addons` 是指向主工作树的软链接。要在 V9 worktree 上编译，编译期间把它们指向 worktree，编译后还原：

```sh
cd /home/arongw/openvela
./build.sh /home/arongw/openvela/worktrees/contest2026_031_niudanxianqianchong-lvgl-v9/board/esp32p4/esp32p4-function-ev-board/configs/smart_home_service_lab -j8
```

上面的手工命令仅展示配置参数；还需要在整个构建期间维护四处源码链接。优先使用第0节的脚本，避免只切换配置却仍编译主工作树。

产物：`/home/arongw/openvela/nuttx/nuttx.bin`。当前版本的大小、SHA-256和构建结果需由本次实际构建确认，不沿用历史固件数值。`savedefconfig`失败也按失败处理，不忽略退出码。

## 2. 生成数据镜像

```sh
cd /home/arongw/openvela/worktrees/contest2026_031_niudanxianqianchong-lvgl-v9
OPENVELA_ROOT=/home/arongw/openvela OUT_DIR=/home/arongw/openvela/out/p4x_littlefs_data \
  ./scripts/make_p4x_littlefs_data_image.sh
```

产物：`/home/arongw/openvela/out/p4x_littlefs_data/data_lfs.bin`，实测 10,485,760 B（分区 0x600000 起，10 MiB 上限）。`OPENVELA_ROOT` 必须指向 openvela 根：worktree 里脚本默认推导出的上级目录是 `worktrees`，找不到 `vendor/artinchip/tools/scripts/mklittlefs`。
镜像包含 `res/fonts/MiSans-Normal.ttf`、`res/icons/*.png`、`res/devices/*.png`；默认不含 `secrets.json`，需要联网测试时用 `WITH_SECRETS=1` 显式带上。

## 3.0 先备份（推荐）

烧录会覆盖板上现有固件。烧之前先把 16 MiB flash 整体读出来，出问题可以原样写回：

```sh
./scripts/v9_board_measure.sh --backup
# 等价手工命令：
# myenv/bin/esptool.py --chip esp32p4 --port /dev/ttyACM0 --baud 921600 \
#   read_flash 0x0 0x1000000 out/board_backup_<ts>.bin
```

回滚：

```sh
myenv/bin/esptool.py --chip esp32p4 --port /dev/ttyACM0 --baud 921600 \
  write_flash -fs 16MB -fm dio -ff 80m 0x0 out/board_backup_<ts>.bin
```

注意：`read_flash` 需要把芯片复位进下载模式，板上正在跑的固件会被打断——这一步本身就不是“只在旁边看着”的操作。

## 3. 烧录

```sh
cd /home/arongw/openvela
myenv/bin/esptool.py --chip esp32p4 --port /dev/ttyACM0 --baud 921600 \
  write_flash -fs 16MB -fm dio -ff 80m \
  0x2000 nuttx/nuttx.bin \
  0x600000 out/p4x_littlefs_data/data_lfs.bin
```

`0x2000` 是 P4 的 Simple Boot 入口，写 `0x0` 会陷入复位循环（见 `docs/开发日志/烧录/README.md`）。

## 4. 采集日志

```sh
python3 - <<'PY'
import serial, sys, time
port = serial.Serial('/dev/ttyACM0', 115200, timeout=0.2)
with open('board.log', 'ab', buffering=0) as out:
    end = time.time() + 3600
    while time.time() < end:
        data = port.read(4096)
        if data:
            sys.stdout.write(data.decode('utf-8', 'replace'))
            out.write(data)
PY
```

也可以直接用 `screen /dev/ttyACM0 115200 -L`，日志会写到 `screenlog.0`。

## 5. 逐场景操作

每个场景**停留 15 秒以上**（至少 3 个 5 秒窗口），切换前后各执行一次 `free`。

开始每个场景前在 NSH 敲一条标记，日志里会多出一行 `MARK P03`，汇总脚本据此把窗口精确归到场景：

```sh
echo MARK P03
```

不打标记也能跑，但要退回到按 `scene=` 分组，那时 P02 和 P03 会混在一起。

| 编号 | 操作 | 关键观察 |
| --- | --- | --- |
| P01 | 上电到屏保/首页出现 | 启动耗时、首帧、堆起点 |
| P02 | 首页静止 + 左右横滑卡片区 | 滚动是否掉帧 |
| P03 | 首页 1 / 3 / 全部设备卡（用房间筛选切换） | 卡片数对帧耗时的影响 |
| P04 | 点卡片开关，等米家回读 | 提交到状态刷新是否卡顿 |
| P05 | 聊天发一条长回复，等流式结束 | 流式期间的帧耗时 |
| P06 | 设置 → 模型分类，弹出软键盘输入 | 键盘展开态帧耗时 |
| P07 | 首页摄像头卡 → 打开预览 → 关闭 → 返回 | 关闭时是否阻塞 |
| P08 | 设置 → MCP/Node 连接与断开 | 连接期 UI 是否卡住 |
| P09 | 静置进入屏保 → 触摸唤醒 | 切换耗时 |
| P10 | 断网 → 恢复 | 状态图标与重连 |
| P11 | 写入失败/重启 | 恢复后设备列表 |
| P12 | 相机预览 + 语音 + 模型对话同时进行 | 满载余量 |

## 6. 汇总

```sh
python3 scripts/v9_perf_report.py board.log --out report.md
python3 scripts/v9_perf_report.py board.log --fill docs/开发日志/应用/2026-10-31-V9-P01-P12-回填表.md
python3 scripts/v9_perf_report.py board.log --gate --image-bytes 10485760 --stability-ok
```

三条命令分别做：输出汇总表、把数值写进回填表对应行、按六条闸门判定动画能否开启。`--image-bytes` 填含动画包的数据镜像字节数，`--stability-ok` 表示 10 分钟观察无复位/丢触。

输出按 `scene` 聚合的表格：窗口数、总帧数、平均帧耗时（按帧加权）、最坏帧、峰值堆占用、最低剩余、最小最大块。

固件每 5 秒输出一行：

```text
[v9-perf] frames=151 avg_ms=12 max_ms=48 heap_used=734112 heap_free=1823744 heap_largest=1032192 scene=home
```

- `avg_ms` 是窗口平均值、`max_ms` 是窗口内最坏单帧，**都不是 p50/p95/p99**；需要严格分位时要在 Host 侧逐帧采样。
- `heap_*` 来自 `mallinfo()`（umm 用户堆，LVGL 对象与业务缓冲所在堆）。
- `scene` 取当前活动屏幕；弹窗叠加在所属页面上，不单独计数。


## 6.1 Host 回归基线（可选）

板端数据回来前后都可以跑一次，用来判断某个改动是不是把绘制开销推高了：

```sh
cmake --build /tmp/sh-lvgl-tests -j8
SMART_HOME_HOST_PERF=1 /tmp/sh-lvgl-tests/panel_check | grep host-perf
```

输出形如 `[host-perf] scene=home samples=300 p50_us=5214 p95_us=6235 p99_us=8908 max_us=9847 ...`。这是 x86 上的整屏重绘开销，**不是板端帧率**，只用于回归对比；当前基线见 M6 记录。

## 7. 像素帧动画准入闸门

`CONFIG_SMART_HOME_V9_DEVICE_ANIMATION` 默认 `n`，静态开/关图是当前降级策略。只有下列条件**全部满足**才允许打开：

| 条件 | 阈值 | 依据 |
| --- | --- | --- |
| P03 与 P12 的窗口平均帧耗时 | ≤ 33 ms | 30 fps 预算 |
| P03 与 P12 的最坏帧 | ≤ 80 ms | 不出现可感知卡顿 |
| P12 的 `heap_largest` | ≥ 1,310,720 B（1.25 MiB） | 1 MiB 动画缓存 + 余量 |
| P12 的 `heap_free` | ≥ 1,048,576 B（1 MiB） | 相机/语音峰值后再留余量 |
| 数据镜像加入动画包后 | ≤ 10 MiB | 分区上限 0xa00000 |
| 连续 10 分钟操作 | 无看门狗复位、无触摸丢失 | 稳定性 |

任一条件不满足就保持 `n`，并在 M6 记录里写明“动画未启用，原因=具体指标”，不得把“未启用”写成“性能已通过”。
