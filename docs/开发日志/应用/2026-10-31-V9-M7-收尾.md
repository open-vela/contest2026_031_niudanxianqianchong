尝试运行 build.sh smart_home_service_lab，configure.sh 报该配置目录不存在。原因是 openvela 构建树解析的是主工作树 contest2026_031_niudanxianqianchong，而 V9 分支与新增 defconfig 位于 worktrees/contest2026_031_niudanxianqianchong-lvgl-v9。目标编译前需要先把 V9 分支合并/复制到主工作树，或为该 worktree 建立独立构建树；这一步属于用户的最终构建流程。

## 目标编译验证结果（2026-10-31，smart_home 配置）

绕过路径问题：构建期间临时把构建树的软链接（board、packages/demos/smart_home）指向 V9 worktree，编译结束立即还原，不改主工作树文件。

编译期发现并修复两个真实缺陷（Host 独立 CMake 构建覆盖不到）：

1. 23d00fe：三个 V9 源文件在 demos/smart_home/Makefile 里只写了路径、漏掉 `CSRCS +=` 前缀，make 报“缺失分隔符”，目标构建根本没进入编译阶段。
2. d344ec3：`pthread_attr_setaffinity_np` 只在 CONFIG_SMP 下声明与链接，摄像头上电代码未加条件编译，非 SMP 配置链接期报未定义引用。

注意：build.sh 收尾会把 `nuttx/defconfig` 回写配置目录，用相对路径参数时该步会打印 `cp` 失败，不影响已生成的固件。

## 配置归档一致性核对（2026-10-31）

编译后把 `nuttx/defconfig`（savedefconfig 生成的最小配置，127 个 CONFIG 行）与归档的 `configs/smart_home_service_lab/defconfig` 按键值排序比对，只有两处差异，都可解释：

| 差异 | 原因 |
| --- | --- |
| `CONFIG_SMART_HOME_NODE_GATEWAY_PORT=18790` 只在归档文件里 | 等于 Kconfig 默认值，savedefconfig 会省略默认值 |
| `CONFIG_NETUTILS_CJSON=y` 只在最小配置里 | 由 `CAGENT_ADDONS_NODE` `select` 带入，defconfig 不记录 select 结果 |

结论：归档配置与实际编译出的配置等价，不存在“归档缺项导致下次构建行为不同”的风险。

## smart_home_service_lab 已可链接（cAGENT V2 适配）

该配置启用 MCP/Node，Kconfig 会 `select CAGENT_ADDONS`。此前链接失败的原因是 `packages/cagent_addons` 与两个 smart_home addon 仍按 cAGENT V1 编写。379ed7c 完成适配：

| 位置 | V1 | V2 |
| --- | --- | --- |
| remote_tool.c 执行回调 | `agent_tool_call_t` + `agent_tool_result_t` | `agent_tool_context_t` + `agent_text_sink_t` |
| 工具注册字段 | `char *` + `group_id` + `timeout_ms` | `agent_string_view_t` + `group`（超时由 descriptor 与 ctx deadline 合成） |
| flag / 错误码 | `AGENT_TOOL_FLAG_*`、`AGENT_ERROR_NOTFOUND`、`AGENT_ERROR_NETWORK` | `AGENT_TOOL_*`、`AGENT_ERROR_NOT_FOUND`、`AGENT_ERROR_IO` |
| MCP 的 TLS | `ov_tls_*`（`cagent/runtime_openvela.h`） | `agent_port_openvela_tls_*` 的 webclient ops |
| 区域诊断 | `ov_mem_region_log` | `smart_home_memory_log_region`（宏映射） |

结果：LD nuttx 成功，nuttx.bin 1,476,972 B，sram 263,928 B / 978,880 B（26.96%），irom 960,876 B，Host 回归 8/8。

需要说明的边界：

- TLS 走阻塞适配层，证书策略沿用量产前的 `AGENT_OPENVELA_TLS_VERIFY_OPTIONAL`（校验证书链但只记录结果），与 V1 行为一致。
- MCP over TLS 与 Node 网关的真实链路只能在板上验证，本轮只到编译链接。
- 参数视图不是 NUL 结尾，执行路径用目录内单一缓冲转换；执行本身由 `active_execution` 串行化，换并发模型时要重新检查该缓冲。
