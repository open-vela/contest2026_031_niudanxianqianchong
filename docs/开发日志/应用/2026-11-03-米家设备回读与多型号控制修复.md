# 米家设备回读与多型号控制修复

## 问题

摄像头“宽动态范围模式”已返回 `true`，面板仍在 10 秒后提示未收到确认。
PC 返回 `data.properties`，板端按 `data` 数组解析，并跳过布尔值。

## 修改

| 文件 | 修改 |
| --- | --- |
| `smart_home_miloco_protocol.c/.h` | 兼容新旧状态响应；校验外层及单项错误码、布尔/整数类型、枚举原值和范围步长；无效/缺失状态标为不可用；校验控制回复中的实际执行结果 |
| `smart_home_miloco_service.c` | 接入解析；下发前使目标旧值失效；回读失败不伪造状态；电源 IID 从唯一的 `on` 布尔属性取得 |
| `smart_home_miloco_specscan.c` | 按设备规格识别；支持 `0.0` 等等价整数；拒绝重复/截断 IID、重复/超限枚举及带参数动作 |
| `smart_home_miloco.h` | 增加有效性与观测序号；容量从每设备 8 项/每枚举 4 档扩展为 16 项/8 档；加长功能与选项名称 |
| `smart_home_lvgl_device_dialog.c` | 新的有效回读匹配才确认；无状态回读的属性仅显示网关接受；无效状态禁用；同步控件及选项容量 |
| `smart_home_lvgl_panel.c` | 兼容设备页的 8 档枚举分行显示，避免越界重叠 |
| `smart_home_v9_device_view.c`、`smart_home_lvgl_home_v9.c` | 首页不以型号推断远程视频/暂停能力；米家摄像头显示开关状态，不显示虚假“预览中” |
| Make/CMake 与测试 | 注册协议模块；增加服务调用链、不同设备规格和真实 LVGL 开关回归 |

多个 `on` 属性可能分别代表主开关和指示灯：不猜测首页快捷开关，详情仍按 IID 分别操作。

## 兼容范围

支持布尔开关、int32 可表示的整数枚举、整数范围和无参数动作。
字符串、小数步长、带参数动作、超过 8 档的枚举暂不暴露为可操作控件；
设备最多显示 16 项。未声称已覆盖全部小米型号和全部 MIoT 数据类型。

RV32 单设备快照为 5412 B，服务的四份 16 设备缓存合计约 338 KiB；
缓存均由堆持有，不放线程栈。当前目标开启 PSRAM user heap。
目标编译的 `parse_device_spec` 自身栈帧为 5392 B、状态应用为 192 B；
这些数值不代替板端堆余量和线程栈高水位。
