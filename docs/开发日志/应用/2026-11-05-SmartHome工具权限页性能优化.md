# SmartHome 工具权限页性能优化

## 问题

点击分类时，UI 线程同步枚举工具并删除、重建整个列表。重复进入也会重建，长说明增加文本布局与首次绘制负担。

## 修改

- 点击先显示页面；40 ms 定时器单次只读取目录或更新一张卡片，全部 LVGL 操作保留在 UI 线程。
- 固定复用三张卡片，分页浏览完整目录；目录和可见内容不变时保留控件与文本。
- 两份有容量上限的目录缓存重复使用；忙碌、分配失败时保留已显示内容。
- 使用 V9 配色、圆角和字号，显示工具来源及权限状态，完整说明按需打开详情。
- Node／MCP 权限仍由接入策略管理；本地开关失败恢复原状态，目录重排不会改变旧控件对应的工具。
- 离开分类暂停更新，返回继续；销毁设置页时删除定时器并释放缓存。

## 验证

- LVGL 主机构建和 CTest：21/21 通过。
- 设置页 ASan／UBSan 回归通过；关闭泄漏检测，仅作为内存访问与未定义行为检查。
- 当前 ESP32-P4 SMP SmartHome 配置下，设置模块对象交叉编译通过；未重新链接固件或烧录。
- 实际 LVGL 已渲染工具页、第二页、详情和显示页。工具卡片为 704 × 74，最后一张卡片底边与分页按钮之间保留 16 px；布局断言验证无越界。
- 相对旧设计，保留整体外壳，有意将长列表改为三张分页卡片；详情和第二页无独立设计参照；内容区像素差异不作为性能结论。

## 板端复核

构建、烧录 SmartHome 后，检查首次进入、重复进入、逐页浏览、详情关闭、本地权限切换及聊天占用时回退。观察 `[v9-tools]` 的 `snapshot_ms`、`row_max_ms` 和 `[v9-perf]` 日志；前两项仅统计目录复制与卡片绑定，不包含屏幕实际绘制耗时。板端响应时间仍需实测。
