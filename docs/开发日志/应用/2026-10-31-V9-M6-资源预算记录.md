# 2026-10-31 V9 M6 资源与性能记录（待目标板填写）

## 目的

记录 V9 首页、聊天、设置、屏保、相机、语音与模型组合场景的帧耗时、内存和 Flash 预算。
**当前没有目标板测量数据，不能把本文模板当作已通过。** 板端采集需要烧录 `smart_home_service_lab`，目前阻塞在烧录授权（见 M7 记录《阻塞项：P01–P12》）。

## 采集开关

在目标 defconfig 中打开：

```ini
CONFIG_SMART_HOME_V9_PERF_LOG=y
```

固件每 5 秒输出一行，同时带出用户堆快照：

```text
[v9-perf] frames=151 avg_ms=12 max_ms=48 heap_used=734112 heap_free=1823744 heap_largest=1032192
```

- `frames/avg_ms/max_ms`：本窗口内 LVGL 单次 `lv_timer_handler()` 的帧数、平均与最坏耗时。
- `heap_used/heap_free/heap_largest`：`mallinfo()` 的 `uordblks/fordblks/mxordblk`，即 umm 用户堆（LVGL 对象与业务缓冲所在堆）。

同时记录：

- 启动日志中的 PSRAM 识别与用户堆大小
- `free`/堆诊断、最大连续块
- 相机开启/关闭前后的内存与 worker 栈高水位
- LittleFS 镜像实际字节数、会话文件峰值
- 固件 ELF/BIN 与资源清单 SHA-256

## 采集方法（板端一次串口会话即可回填）

1. 烧录 `smart_home_service_lab`（含 `CONFIG_SMART_HOME_V9_PERF_LOG=y`），串口日志重定向到文件。
2. 每个场景开始前在 NSH 敲 `echo MARK P03`（编号随场景替换），停留 15 秒以上（至少 3 个 5 秒窗口），切换前后各做一次 `free`。标记让汇总脚本把窗口精确归到场景；不标记只能按 `scene=` 粗略分组，P02/P03 会混。
3. 从日志里按时间戳切出该场景的 `[v9-perf]` 行，取 `avg_ms` 的最大值作为 p95 近似、`max_ms` 作为最坏帧，`heap_used` 取窗口内的峰值。
4. 把数值填进下方场景表的对应列，并附上日志片段路径。

完整命令（构建、数据镜像、烧录、串口采集、汇总脚本）见 `2026-10-31-V9-板端实测运行手册.md`；汇总用 `scripts/v9_perf_report.py board.log --out report.md`。

注意：`avg_ms` 是窗口平均值，不是 p50/p95/p99 分位数；CSV 表格里的“p50/p95/p99”如需严格分位，要在 Host 侧用逐帧采样统计，板端只提供平均值与最坏值。

## Host 参考基线（2026-10-31，非板端）

板端 P01–P12 尚未采集。为避免“完全空白”，这里先给出 Host 侧的可复现基线，用途只有一个：**改动前后对比回归**，不能当作板端帧率，也不能替代 P01–P12。

采集命令：

```sh
cmake --build /tmp/sh-lvgl-tests -j8
SMART_HOME_HOST_PERF=1 /tmp/sh-lvgl-tests/panel_check | grep host-perf
```

实现：`test_panel.c` 里的 `test_host_frame_budget()`，在 V9 首页（6 张卡）上循环 300 次“整屏失效 + `lv_refr_now()`”，统计单帧耗时分布。

| 场景 | 采样数 | p50 | p95 | p99 | max | 测量时刻堆占用 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| V9 首页整屏重绘（Host x86） | 300 | 5.2 ms | 6.2 ms | 8.9 ms | 9.0–9.8 ms | 188,944 B |

三次连续运行的离散度：p50 5.21–5.30 ms，p95 6.23–9.01 ms，p99 8.90–9.18 ms。

判读边界：Host 没有 DSI 扫描输出、没有 RGB565 传输、也没有 P4 的 400 MHz 单核调度，只能说明“对象树与绘制代码的 CPU 开销量级”，板端数字必须以 `[v9-perf]` 为准。

## 动画策略与准入闸门

`CONFIG_SMART_HOME_V9_DEVICE_ANIMATION` 默认 **n**，使用静态开/关图。打开的唯一判据是下面六条同时成立（取自 `2026-10-31-V9-板端实测运行手册.md` 第 7 节）：

| 条件 | 阈值 |
| --- | --- |
| P03 与 P12 窗口平均帧耗时 | ≤ 33 ms |
| P03 与 P12 最坏帧 | ≤ 80 ms |
| P12 `heap_largest` | ≥ 1,310,720 B |
| P12 `heap_free` | ≥ 1,048,576 B |
| 数据镜像加入动画包后 | ≤ 10 MiB（0xa00000） |
| 连续 10 分钟操作 | 无看门狗复位、无触摸丢失 |

没有预算数据时，不把“动画未开启”写成“性能已通过”；未达标时在本文记录“动画未启用，原因=具体指标”。

## 静态占用实测（2026-10-31）

V9 分支在两个目标配置下都成功链接（见 M7 记录），链接期区域占用如下。这是**静态镜像**数据，与上表的**运行期堆/PSRAM 预算**不是同一口径，不能替代 P01–P12。

| 区域 | smart_home | smart_home_service_lab | 容量 |
| --- | ---: | ---: | ---: |
| irom_seg | 919,308 B（1.37%） | 960,876 B（1.43%） | 64 MB |
| sram_seg | 247,416 B（25.28%） | 263,928 B（26.96%） | 978,880 B |
| drom_seg | 1,395,188 B（2.08%） | 1,400,572 B（2.09%） | 64 MB |
| tcm_idram_seg | 104 B | 104 B | 8 KB |
| lp_ram_seg | 104 B | 104 B | 32,744 B |
| nuttx.bin | 1,435,404 B | 1,476,972 B | — |

service_lab 多出的 41,568 B irom 与 16,512 B sram 来自 MCP/Node 附加模块。sram_seg 约 27%，内部 SRAM 仍有约 715 KB 余量；V9 首页的 LVGL 对象树走 PSRAM 堆，不占这一段。运行期字体内存、双缓冲、相机链路仍以 P01–P12 为准，采集方法见上。
