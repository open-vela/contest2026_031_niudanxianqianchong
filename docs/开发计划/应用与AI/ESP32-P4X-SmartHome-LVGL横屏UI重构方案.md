# ESP32-P4X SmartHome LVGL 1024×600 横屏 UI 重构方案

> 状态：已实施。原生 LVGL 已是交付路径，QuickApp UI 不参与交付。V9 界面在
> `src/ui/lvgl/` 下落地，`smart_home` 与 `smart_home_voice` 均以它为默认界面。
> 本文保留重构边界与实施顺序的约定。
>
> 目标平台：ESP32-P4X Function EV Board、EK79007 1024×600 横屏、GT911 触摸。
>
> 视觉参考：[1024×600 网页交互原型](../../../quickapp/smart_home_ui/prototype-web/index.html)。
> 网页原型只作为布局、状态层级和交互节奏的评审稿，不是运行时技术方案。

## 1. 决策与边界

近期产品 UI 选择 **Native LVGL**，不以 QuickApp、RPK、Feature IPC 或 VAPP 能否启动作为
面板体验的前置条件。原因是当前 P4X 首要验证对象是显示、GT911、设备控制、cAGENT、网络和
摄像头等原生链路；LVGL 可直接消费这些服务的状态，避免再引入一层运行时和跨进程状态同步。

本次重构的目标是将现有偏“设备管理工具”的三页 LVGL 界面，调整为墙面中控的五个一级页面：

```text
屏保 ──上滑──> 首页 ──┬──> 设备（按空间）──> 设备详情抽屉
                     ├──> 场景
                     ├──> 安防 ──> 原生监控/摄像头预览
                     └──> 更多 ──> 系统设置 / Agent
```

不在本期范围内：卡片编辑、拖动排序、远程下载主题、首页连续视频预览、第三方素材直接进固件、
以及 QuickApp UI 的打包与部署。已有 QuickApp 契约和代码可以保留为独立探索，不应成为
`CONFIG_SMART_HOME_DEMO_UI_LVGL=y` 的依赖。

## 2. 设计基线

### 2.1 固定画布与安全区

以 1024×600 为设计坐标；横屏真机不做等比缩放的“网页截图式”排版。若未来需适配其他分辨率，
按容器比例和最小触控尺寸重新布局，而非直接缩放字体和图标。

| 区域 | 设计值 | 规则 |
| --- | ---: | --- |
| 顶栏 | 64 px | 左侧品牌/返回语义，右侧麦克风、摄像头、勿扰、网络、时间；只显示状态，不承担控制。 |
| 主体 | 472 px | `y=64..536`，左右边距 28 px，卡片间距 10 px。 |
| 底部导航 | 64 px | 固定 5 项：首页、设备、场景、安防、更多；单项有效区域不小于 68×56 px。 |
| 卡片 | 圆角 17 px | 轻边框或单层弱阴影二选一；不使用实时模糊。 |
| 控件 | 圆角 11 px | 开关、加减、确认等最小触控面建议 44×44 px。 |

首页主体采用网页原型已验证的两行异构网格：

```text
┌──────────────────────────────────────────────────────────────────────┐
│ OpenVela HOME                   麦克风  摄像头  勿扰  网络    10:28 │
├──────────────┬──────────┬──────────────────────┬────────────────────┤
│              │ 高频场景 │ 空调伴侣             │ 摄像头摘要         │
│ 天气环境大卡 ├──────────┼──────────────────────┼────────────────────┤
│              │ Agent    │ 音乐摘要             │ 家庭状态           │
├──────────────┴──────────┴──────────────────────┴────────────────────┤
│                   首页    设备    场景    安防    更多                │
└──────────────────────────────────────────────────────────────────────┘
```

首期首页格位固定，**没有编辑、删除、添加和拖动重排模式**。房间信息显示在设备/场景卡内；
首页不再放“全屋、客厅、主卧、厨房”筛选条，空间筛选只属于设备页。

### 2.2 `light-calm` 视觉令牌

以网页原型的柔和浅色为首期唯一主题，避免旧页面、弹窗和新增页面混用深浅两套设计。令牌必须
集中定义，页面不得散落硬编码颜色。

| 语义 | 推荐值 | 用途 |
| --- | --- | --- |
| `canvas` | `#F4F2EE` | 页面画布 |
| `surface` / `card` | `#FBFAF8` / `#FFFFFF` | 顶栏、底栏、卡片 |
| `text` / `subtext` | `#26312E` / `#74807B` | 主次文字 |
| `line` | `#E5E1DA` | 细分隔与轻边界 |
| `active` / `active-text` | `#E6F0EA` / `#286A4B` | 已选导航、已开启低风险状态 |
| `weather` | `#E9F3F4` | 环境卡 |
| `comfort` | `#FAEBE3` | 空调、舒适度卡 |
| `safe` | `#EAF2EB` | 正常安防、健康状态 |
| `service` | `#F1EDF8` | Agent、服务状态 |
| `danger` | `#D64545` | 仅告警、失败与高风险确认 |

摄像头区域允许呈现深色视频/缩略画面，但它是内容层；其外部页背景、操作栏、抽屉和状态标签
仍遵守上述浅色令牌。渐变只能预渲染或限制在小卡片背景；禁止实时全屏 Blur、全屏 alpha
遮罩叠加和持续粒子动画。

### 2.3 字体、图标与素材

- 字体使用现有 LVGL 可用字体，首期规格为 12/14/16/20/32 px；时间和温度可使用 32 px，
  不为了装饰额外引入大字号字体文件。
- 图标按照 20/24/32/48 px 四级导出；顶栏与导航主用 20/24 px，设备卡主图标用 32 px，
  详情主视觉最多 48 px。
- 现有 `src/ui/lvgl/icons/*.c` 与 `images/smart_home_icons.h` 可继续承载已编译图标。
  新图标优先从授权 SVG 源稿统一栅格化为 LVGL C 数组或目标尺寸 PNG，不在运行时解析 SVG。
- `prototype-web/assets/icons/` 当前是用户提供、许可证未登记的评审素材，**不得直接编译、
  打包或提交**。每项资源须先登记来源、许可证、设计尺寸、色彩和对应 LVGL 符号。
- 锁屏壁纸可使用授权 JPG/PNG 的单张静态背景，但解码后必须释放；不能与摄像头帧缓冲、
  多张大卡片背景同时常驻内存。

## 3. 页面与交互规格

### 3.1 屏保

屏保只显示家庭名称、时间、日期天气、网络状态和一行家庭摘要，采用低刷新或静态背景。上滑
进入首页；任意高优先级安防事件应唤醒并进入安防提醒，而不是先显示普通首页。

屏保不启动网络轮询、Agent 请求或摄像头预览；进入首页时读取最新快照。建议在无操作一段时间
后由 LVGL 定时器进入屏保，离开屏保时只恢复需要的页面定时器。

### 3.2 首页

首页仅展示家庭最重要状态和高频低风险操作：

| 卡片 | 可见信息 | 直接操作 | 跳转 |
| --- | --- | --- | --- |
| 天气环境 | 时间、天气、温湿度/空气摘要 | 无 | 环境相关设备页 |
| 高频场景 | 一个场景名称、房间 | 执行已授权场景 | 场景页 |
| 空调伴侣 | 房间、模式、设定温度、开关 | 开关、`− / +` | 空调详情 |
| 摄像头摘要 | 在线、最近缩略图或占位 | 无连续预览 | 安防页 |
| Agent | 家庭摘要或一句问候 | 打开 Agent 底部/侧边 Sheet | Agent 对话 |
| 音乐摘要 | 曲目、房间、播放状态 | 上一首、播放、下一首 | 媒体详情 |
| 家庭状态 | 一项重要摘要或异常 | 无 | 对应设备/安防页 |

开关、温度加减、场景执行只能乐观显示局部“执行中”，收到 `smart_home_device` 或 Agent 的最终
结果后才更新正式状态；失败时在本卡提示，不跳转、不整屏阻塞。门锁、撤防等高风险能力不放入
首页，必须在详情页执行确认。

### 3.3 设备页与设备详情

设备页以**空间**为第一筛选维度：`全部 / 客厅 / 卧室 / 厨房 / 卫生间`。设备类型只是属性，
用于图标和详情能力组合，不能替代空间分类。卡片只展示名称、房间、一个主状态和独立开关；
点击卡片主体进入详情，不把整张卡片绑定为开关。

详情采用右侧抽屉（约屏宽 65%，遮罩仅覆盖必要区域），顺序固定为：

```text
设备身份栏（返回、名称、房间、在线状态）
主控区（开关与主参数）
模式/参数区（亮度、色温、温度、风速、开合度等）
低频设置与诊断
```

灯光、窗帘、空调先落地为三种模板；门锁/安防采用单独高风险模板。摄像头在详情仅显示在线、
预览入口、隐私状态和设置，不在抽屉内复制连续画面。

### 3.4 场景、安防、更多与系统设置

- **场景**：展示固定的常用场景与最近执行结果；执行可撤销的低风险场景直接确认，涉及门锁、
  布撤防等敏感设备时进入二次确认。
- **安防**：展示布防状态、门窗/传感器摘要、事件列表和“进入监控”。连续摄像头预览使用原生
  Monitor/CameraPreview 组件或独立 native screen；LVGL 仅管理进入、退出、叠加状态与告警。
- **更多**：提供智能管家、能耗、家庭成员、系统设置等低频入口；它是收纳页，不做第二个首页。
- **系统设置**：保留现有模型后端、工具目录、Skills、网络与系统健康能力，但按“顶部摘要卡 +
  分组内容/可折叠区”重排。密钥只呈现“已配置/未配置”，绝不回显原文。
- **Agent**：从原有一级 `Chat` 页改为由首页/更多打开的 Sheet；保留现有异步 worker、消息气泡
  与工具轨迹。Agent 的执行结果仍通过 UI 线程队列回投，不允许 worker 直接调用 LVGL。

## 4. LVGL 架构重构

### 4.1 保持的边界

`smart_home_agent_app_t`、`smart_home_state_t`、`smart_home_device_service`、场景/Skills/工具和
cAGENT 继续是状态与业务层。UI 不读取 GPIO、Wi-Fi、摄像头驱动或模型密钥，也不重新实现设备
规则；它只请求业务层动作并订阅确认后的状态。

LVGL 仍只由 `smart_home_lvgl_run()` 所在 UI 线程持有。现有
`smart_home_lvgl_event_cb()` → pending queue → `smart_home_lvgl_process_pending()` 的回投模型
必须保留，所有页面刷新、弹窗创建和动画调用均发生在 UI 线程。

### 4.2 建议的模块拆分

现有文件可按职责演进，不建议一次性重写 Agent、设备和设置逻辑：

| 现有模块 | 重构动作 | 目标职责 |
| --- | --- | --- |
| `smart_home_lvgl.c` | 保持初始化、显示、事件队列与运行循环 | 生命周期与 UI 线程边界 |
| `smart_home_lvgl_style.[ch]` | 重写为统一令牌、字体、卡片、按钮、标签 helper | 唯一视觉入口 |
| `smart_home_lvgl_nav.c` | 从 3 项改为 5 项固定底栏 | 一级导航、页面切换 |
| `smart_home_lvgl_panel.c` | 拆为 `home` 与 `devices` 实现 | 首页卡片与空间设备列表 |
| `smart_home_lvgl_chat.c` | 改为 Agent Sheet，保留异步消息逻辑 | 对话、工具轨迹、风险确认 |
| `smart_home_lvgl_settings.c` | 重排为设置摘要和分组 | 模型、工具、Skills、系统状态 |
| 新增 `*_scenes.c` / `*_security.c` / `*_screensaver.c` | 按页面独立实现 | 避免所有业务堆入 panel |
| 新增 `*_detail.c` | 统一右侧详情抽屉和设备模板 | 精细控制与确认 |

`smart_home_lvgl_t` 不再以 `screen_panel/chat/settings` 作为产品模型，建议演进为 `screen_home`、
`screen_devices`、`screen_scenes`、`screen_security`、`screen_more`，并增加 `screensaver`、
`agent_sheet`、`detail_sheet` 等覆盖层句柄。迁移期间可保留旧字段作为兼容层，但每完成一个页面
就删除其旧的专用控件字段，避免双份 UI 状态长期共存。

### 4.3 状态和刷新策略

建立 UI 本地只读投影，至少包含：当前页面、当前房间、当前详情设备 ID、屏保状态、弹层状态、
设备 revision、场景执行状态、安防摘要和 Agent 请求状态。业务层状态变化根据影响范围做局部更新：

```text
设备状态变更 -> 对应设备卡 + 已打开详情抽屉 + 首页相关摘要
场景结果     -> 场景项 + 首页场景卡 + Toast
安防事件     -> 安防页 + 首页家庭状态卡；高优先级时唤醒屏保
Agent 事件   -> Agent Sheet；工具结果仅刷新相关设备/场景
```

禁止“任一事件都 `lv_obj_clean()` 整个页面再重建”。这会造成帧抖动、焦点丢失和 PSRAM 峰值。
首次进入页面构建静态骨架；后续只写标签、状态样式、图片源和必要列表项。

## 5. 摄像头、内存与性能

摄像头实时预览不能把每帧 JPEG/像素数据复制到普通 LVGL 图片对象，也不经 Agent 线程处理。
建议链路为：摄像头采集/解码 → 原生预览 buffer 或 native monitor → 安防全屏承载；LVGL 只负责
入口、控制栏、隐私/在线状态与 AI 检测结果叠加。首页始终只是缩略图、静态占位或最后一帧。

复杂交互页以 **30 FPS** 为验收目标（帧周期约 33 ms）：

- 页面切换/抽屉出现：动画时长 160–220 ms，只动画 `x`、`opacity` 等小区域属性；
- 触摸反馈：按下状态在一个 LVGL tick 内出现；开关/按钮不得等待网络请求完成；
- 单页常驻：一个首页、一个一级页面和一个弹层为上限；离开页面释放大图片与不再使用的对象；
- 图像：卡片背景尽量用颜色/简化几何；静态图片按显示尺寸导出，避免 1024×600 图片作为小卡片；
- 诊断：在 P4X 上记录 `lv_timer_handler()` 耗时、heap/PSRAM 余量、图片解码峰值、连续预览时
  的帧率和触摸延迟。

## 6. 分阶段实施与验收

### L0：冻结基线和设计令牌

1. 以网页原型锁定首页网格、五项导航、浅色令牌、设备抽屉和屏保交互。
2. 新建 LVGL 布局/样式 helper，替换 320×240 默认尺寸和当前三项英文导航的假设。
3. 验收：在 1024×600 framebuffer 上显示统一顶栏、底栏、空白首页骨架；不启动第二个
   `lv_init()`，不改变设备/Agent 业务行为。

### L1：首页、屏保和本地 Mock 状态

1. 实现屏保上滑进入首页、七个固定首页格位、顶栏状态和局部 Toast。
2. 先接入 `smart_home_state_t` 内已有环境、灯光和空调数据；不可用能力显示明确的空状态。
3. 验收：首页操作不影响导航，空调 `− / +`、开关在真实设备确认后回写；连续操作无对象泄漏。

### L2：空间设备页与三类详情模板

1. 实现房间筛选、设备卡局部刷新、灯光/空调/窗帘右侧抽屉。
2. 将当前设备编辑/模拟环境调试能力下沉为受控开发入口，不占产品首屏。
3. 验收：每个设备卡与详情控制状态一致；离线、执行中、失败三态可辨；高风险能力不会从卡片
   主体直接执行。

### L3：场景、安防、更多和设置重排

1. 接入场景目录与执行结果；完成安防事件流、更多页和设置摘要。
2. 将 Agent 从底栏迁为 Sheet，同时保留工具轨迹和二次确认。
3. 验收：五项底栏可达；安防事件能从屏保唤醒；密钥不回显；网络/模型不可用时页面可用且说明明确。

### L4：原生摄像头、资源和性能验收

1. 在安防页接入原生预览组件和 AI 检测叠加，不改变 LVGL 的单线程原则。
2. 完成图标许可证登记、目标尺寸导出和资源内存预算。
3. 验收：复杂页稳定 30 FPS；预览开启/关闭不造成 UI 卡死、内存持续增长或触摸失效。

## 7. 构建和回归原则

LVGL 产品配置应明确选择：

```text
CONFIG_SMART_HOME_DEMO=y
CONFIG_SMART_HOME_DEMO_UI_LVGL=y
# CONFIG_SMART_HOME_DEMO_UI_QUICKAPP is not set
```

原生 LVGL 的完整功能验证以现有 `smart_home` 配置为基础；P4X 每次合入均使用项目规定的
`build.sh` 流程，而不以网页 Demo 或 QuickApp 构建成功替代真机验证。重构过程中，布局代码、
业务层、摄像头预览和 Wi‑Fi 改动应拆分提交，避免 UI 视觉调整与硬件/网络问题互相掩盖。
