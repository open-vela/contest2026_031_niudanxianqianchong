# ESP32-P4X SmartHome LVGL 性能优化方案

> 状态：分析完成，优化未实施。帧时间为模型估算，以实测为准；P0/P1/P2 指修复优先级。
> 平台：ESP32-P4X Function EV Board + EK79007 1024×600 + GT911。
> 关联：[UI 设计方案](ESP32-P4X-智能家居中控面板UI设计方案.md)、
> [LVGL 横屏 UI 重构方案](ESP32-P4X-SmartHome-LVGL横屏UI重构方案.md)。

## 1. 结论

屏幕卡顿主要不是渲染慢，而是**两处 UI 线程同步阻塞**，其次是全屏转场和字形缓存。
先修阻塞，再谈渲染模式。

## 2. 关键事实

- 1024×600 RGB565，2 块全帧缓冲在 PSRAM，LVGL 用 DIRECT + 双缓冲（`esp32p4_fb.c:41`、`lv_nuttx_fbdev.c:143-154`）。
- 单线程渲染，刷新周期默认 33 ms，动画上限 30 Hz（`lv_conf_internal.h:230`）。
- 启动时一次性构建全部页面，并把 7.9 MB MiSans 预加载到 PSRAM（`smart_home_lvgl.c:64-107`）。
- 面板持续扫描约 74 MB/s，相机预览约 111 MB/s，全屏一帧约 4.9 MB 内存流量。

## 3. 卡点、原因与方案

### P0 硬卡：UI 线程被同步阻塞

| 现象 | 原因 | 解决方案 |
| --- | --- | --- |
| 退出安防页先定住 ~0.2 s 才切页 | `load_tab` 在 UI 线程调 `smart_home_camera_stop()`，内部 `pthread_join` 等采集线程；线程可能正卡在 200 ms 的 `poll` 里（`nav.c:58` → `pages.c:277` → `camera_service.c:539`，超时 `camera_service.c:42`） | 停止只置标志立即返回；join、STREAMOFF、释放缓冲交给低优先级 worker 或空闲时执行；先切页动画，再回收 |
| 设备页每次开关顿一下，传感器变化时每秒顿 | 状态一变就 `lv_obj_clean()` 整张网格并重建全部卡片（`panel.c:953/2069`）；米家轮询 1 s，值变化即 `revision++`（`service.c:521` → `panel.c:2034`） | 卡片只建一次，状态变化只改 label、switch 和样式；只有设备集合或筛选变化才重建。这也符合重构方案“禁止整页 clean 再重建”的原则 |

### P1 掉帧与首开卡

| 现象 | 原因 | 解决方案 |
| --- | --- | --- |
| 切页在动，但一顿一顿 | 180 ms 全屏 `MOVE`，每帧整屏重绘；33 ms 刷新只有约 5 帧，DIRECT 双缓冲还要同步另一页（`nav.c:109`、`lv_refr.c:412`） | P4 改瞬时切换或 120 ms 内容淡入；保留滑动时，转场期间把刷新周期降到 16 ms |
| 第一次打开设置/聊天顿一下 | TinyTTF 全局只有 128 个字形缓存，5 档字号共享，中文页远超 128（`lv_tiny_ttf.c:149`） | 缓存提到 512–1024（注意该版本 `cache_size` 参数未生效，需改常量）或预热常用字；改后复测首开与滚动 |
| 开机到出画面慢 | 全部页面预构建 + 7.9 MB 字体预加载（`smart_home_lvgl.c:64-107`） | 只预建屏保和首页，其余首次进入时建；服务类页面延后；必要时首屏用子集字体 |

### P2 局部优化

| 现象 | 原因 | 解决方案 |
| --- | --- | --- |
| 预览页轻微掉帧 | 每 66 ms 在 UI 线程拷 300 KB 并重绘 512×300，footer 还有 `bg_opa=230` 叠加（`pages.c:382/395`） | 保持 15 FPS；footer 改不透明；无新帧不 invalidate（现有 sequence 判断可复用） |
| 点按响应偏慢 | GT911 20 ms 轮询 + 33 ms 输入/刷新 + ≤10 ms 主循环（`smart_home_lvgl.c:343-353`） | 交互期间刷新降到 16 ms；GT911 轮询视总线余量降到 10 ms |
| 待机越久越慢 | 隐藏页定时器仍在更新 label；整页重建会累积堆碎片 | 按 `active_tab` 暂停定时器；P0 的原地更新同时缓解碎片 |

## 4. 修复顺序与验收

1. 先做 P0 两处，消除“点了没反应”的硬卡。
2. 再做 P1 的转场、字形缓存、懒构建。
3. P2 与渲染模式 A/B（DIRECT 双缓冲 → PARTIAL）等有余量再动。

| 指标 | 目标 |
| --- | --- |
| 安防退出到新页首帧 | ≤ 50 ms |
| 设备开关反馈 | ≤ 100 ms，且不重建网格 |
| 页面切换 | p95 ≤ 33 ms，否则改瞬时切换 |
| 首次进入设置/聊天 | ≤ 150 ms |
| 启动首帧 | 先测基线，再定目标 |
| 连续 1 小时待机 | PSRAM 稳定，无累积卡顿 |

## 5. 测量建议

- `load_tab` 打三段点（停摄像头 / 刷新 / 建屏），超过 20 ms 记日志。
- 统计 `rebuild_device_cards` 的调用次数与耗时。
- 开 `LV_USE_PERF_MONITOR` + `LV_USE_SYSMON`，同一脚本重复三次，波动 <10%。
