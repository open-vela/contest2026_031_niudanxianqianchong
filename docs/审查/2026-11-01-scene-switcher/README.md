# 首页场景切换器（2026-11-01）

## 结论

首页房间筛选行右侧新增场景切换按钮，点击展开四项下拉菜单，选中即通过
`run_scene` 对应的 miloco 语义锚点路径直接执行，不再经过 agent。
Host 回归 15/15；ESP32-P4 固件构建与烧录由使用者执行。

## 位置决策

设计稿原「家庭模式」按钮在 (838, 95)，与 128px 天气图标（x 872~1000、
y 58~186）重叠，实测两区域墨迹相互覆盖。因此下移到房间筛选行右侧。

| 项 | 值 | 说明 |
| --- | --- | --- |
| 按钮 | (844, 206) 156×48 | 右边界 1000，与天气图标、卡片区共用 24px 边距 |
| 垂直中心 | 230 | 与房间 chips（y 204~248）同一水平线 |
| 距「+」按钮 | 106px | 「+」在 (532, 200) 48×48 |
| 距下方卡片行 | 6px | 卡片区 y 从 260 起 |
| 墨迹占用 | 0.0% | 放置前实测该矩形内无任何内容 |

## 菜单规格

| 项 | 值 |
| --- | --- |
| 容器 | (844, 252) 156×176，圆角 12，1px `#D8E0DF` 边框 |
| 单项 | 156−12=144 × 40 |
| 内边距 | 6 |
| 选中底色 | `#E1EDF0`（SURFACE_ON） |
| 阴影 | 宽 18，不透明度 20%，y 偏移 4 |
| 挂载 | `lv_layer_top()`，不挂在首页 |

挂到顶层图层是硬性要求：首页最后一个子对象必须是底部导航栏
（`test_panel.c` 与 `test_camera_home.c` 都依赖这个约定）。

## 四个场景

scene id 与 `res/skills/smart_home_scenes.md`、`miloco` 的
`g_miloco_scenes` 逐字一致，改一处必须同步另外两处。

| id | 文案 | 图标 | 资产 |
| --- | --- | --- | --- |
| home | 回家模式 | `asset:home` | 20 / 32 / 48 |
| movie | 观影模式 | `asset:television-classic` | 20 / 32 |
| sleep | 睡眠模式 | `asset:zzz` | 20 / 32 |
| away | 离家模式 | `asset:run` | 20 / 32 |

后三个原本只有 32px，20px 请求会回落成 32px 导致溢出。已在
`scripts/generate_smart_home_lvgl_icons.py` 的 `SMALL_ICONS` 里补入
`run`/`television-classic`/`zzz`，重新生成三个 20px A8 资产。

## 执行路径

点选菜单项 → `v9_scene_run()` → `smart_home_miloco_run_scene()`。
与聊天页 `run_scene` 工具走同一条 miloco 路径，区别只是不经过 LLM 解析。
网关不可达时弹出「场景未执行 / 米家网关未连接」，不静默失败。
