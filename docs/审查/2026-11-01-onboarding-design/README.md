# 首次配置引导设计稿（2026-11-01）

## 设计前提

三个配置项**并列而非串联**，因为它们的重要性和依赖关系不同：

| 配置项 | 必要性 | 缺少时 | 依赖 |
| --- | --- | --- | --- |
| 家庭网络 | 刚需 | 天气/米家/大模型全部不可用 | 无 |
| 米家网关 | 可选 | 用演示卡片代替真实设备 | 网络 |
| 模型服务 | 聊天的刚需 | 聊天页不能对话，其余正常 | 网络 |

因此**不做强制线性向导**：一旦强制，只想用本地设备的人会被迫扫码绑米家，
比赛现场评委也会先看到配置页而不是首页。

## 已知风险

1. **Wi-Fi 扫描是最大不确定项**。NuttX 的 wpa_supplicant 提供 SCAN /
   SCAN_RESULTS，但需要 wpa_ctrl 连接，本项目没有现成封装。如果扫描做不出来，
   02 画面退化为「手动输入 SSID」，价值打对折。
2. **比赛演示**。建议用持久标记记住「已跳过」，且演示镜像预置 secrets.json
   时直接不弹，避免评委看到配置页。
3. **10 个画面过多**。真正必做的只有 01（总览）和 10（完成），中间的 02-09
   是把现有弹窗换个外壳。建议第一版只做 01 + 跳转，02-09 复用现有面板。
