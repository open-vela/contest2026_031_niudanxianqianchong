## 改了什么

| 项 | 改前 | 改后 |
| --- | --- | --- |
| 形态 | 整页（`page_screen` + 顶栏底栏） | 840×480 弹窗叠在当前页 |
| 入口 | 设置→服务→查看连接状态→打开米家→扫码绑定（四层） | 设置→服务→**配置米家**→保存并扫码授权（两层） |
| 遮罩 | 无（整页） | `#071726` @ 58%，与设计一致 |
| 二维码 | 264 px，黑块 | 256 px 白卡 + 内边距 20，深蓝黑 `#314956` 模块 |
| 状态反馈 | 底部一行文字 | 顶部「网关已连接」+ 底部状态条含**已等待 mm:ss** |
| 按钮 | 返回（无）+ 无 | 「返回配置」次按钮 + 「检查绑定状态」主按钮 |
| 绑定成功 | 2 秒后跳设备页 | 相同（弹窗先关再跳） |

| 项 | 设计 | 实现 | 差 |
| --- | --- | --- | --- |

## 与设计稿的有意差异

1. **设计稿的 34-mi-qr 是「设置页 + 遮罩 + 弹窗」的混合体**，左栏六个分类和右栏三行服务仍然可见。实现里弹窗盖在服务页之上，底图按 58% 暗化，视觉上更干净——这是有意的。
2. **设计稿二维码是占位图**，实现是真实可扫的（内容 `http://<host>:<port>/`）。
3. **多了一个「直接扫码绑定」按钮**（在上一层的「连接米家网关」弹窗里），用于地址已配置过的场景，跳过填写。
4. **底部状态条多了「已等待 mm:ss」**，因为实现是每秒轮询，需要让用户看到它在动。

## 流程

```
设置 → 设备与服务 → 配置米家
   ↓
「连接米家网关」弹窗（地址/端口/令牌）
   ├─ 保存并扫码授权 → 落盘 secrets.json → 打开扫码弹窗
   └─ 直接扫码绑定 ─────────────────────→ 打开扫码弹窗
                                              ↓
                                    扫码 → 手机授权 → 自动检测 → 关弹窗 + 进设备页
```

## 验证

- Host CTest 13/13 通过（含 `panel_check`、`device_dialog_check`、`room_dialog_check`）。
- 像素实测：弹窗 (94,62,837,477) vs 设计 (93,63,838,475)。
- 真实扫码需板端验证（Host 的 QR 编码用固定边框矩阵代替）。
