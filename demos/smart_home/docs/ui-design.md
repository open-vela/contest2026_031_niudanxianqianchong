## 1. 导航设计规范

### 1.0 视觉定位

smart_home 的 LVGL UI 应保持**明亮、高级、产品化**的智能家居中控风格。
背景不建议使用大面积深色。深色界面容易让 demo 呈现工程调试感，也会削弱
家庭设备管理场景应有的清洁、温和和可亲近感。

设计关键词：

| 关键词 | 说明 |
|--------|------|
| Bright | 主背景使用浅色暖白或浅灰，不使用纯黑、深蓝或大面积暗色 |
| Premium | 低饱和配色、克制阴影、清晰层级，避免彩色堆叠 |
| Calm | 智能家居场景应让用户感到稳定、可靠、安静 |
| Agent-aware | UI 要清楚表达 Agent 状态、工具调用和设备状态变化 |
| Embedded | 控件少而准，避免网页式复杂布局和过重装饰 |

推荐整体观感：

```text
浅色背景 + 白色/雾白卡片 + 蓝绿色状态色 + 低对比细边框
```

不推荐：

- 大面积深蓝、黑色、紫蓝渐变背景
- 依赖高饱和霓虹色表现智能感
- 用大量装饰性阴影、发光或 emoji 取代清晰信息结构
- 把 Chat 设计成主屏，弱化设备状态

信息优先级：

```text
Panel    = 主屏，设备状态与快速控制
Chat     = Agent 对话与工具调用链
Settings = 模型 API、运行状态、资源配置
```

### 1.1 导航架构

采用**底部按钮式屏幕切换导航系统**，固定于屏幕底部安全区域内。导航栏包含 3 个核心功能入口：

| 编号 | 图标 | 文字标签 | 功能 | LVGL 屏幕 |
|------|------|---------|------|-----------|
| 1 | 🏠 | 面板 | 设备管理与控制（主屏） | `screen_panel` |
| 2 | 💬 | 对话 | 聊天 + 工具调用链 | `screen_chat` |
| 3 | ⚙ | 设置 | 模型 API、网络和系统配置 | `screen_settings` |

### 1.2 导航栏布局

```
┌─────────────────────────────────────────┐
│                                         │
│           内容区域                       │
│         (可滚动)                        │
│                                         │
│                                         │
├─────────────────────────────────────────┤
│  ┌──────────┐ ┌──────────┐ ┌──────────┐│
│  │    🏠     │ │    💬     │ │    ⚙     ││
│  │   面板    │ │   对话    │ │   设置    ││
│  └──────────┘ └──────────┘ └──────────┘│
│              底部导航栏                   │
└─────────────────────────────────────────┘
```

**尺寸规范**：

| 属性 | 值 | 说明 |
|------|-----|------|
| 导航栏高度 | 56px | 包含图标 + 文字 + 上下 padding |
| 导航栏宽度 | 屏幕宽度 - 2×侧边 padding | 适配圆形屏裁切 |
| 图标尺寸 | 24×24px | 使用 LVGL Symbol 或 Unicode 字符 |
| 文字大小 | 12px | `lv_font_montserrat_12` |
| 按钮间距 | 8px | 均匀分布 |
| 导航栏底边距 | 20px | 避开圆形屏底部弧线裁切 |

### 1.3 激活状态视觉区分

| 状态 | 图标颜色 | 文字颜色 | 背景 |
|------|---------|---------|------|
| 激活 | `#4A90D9` (品牌蓝) | `#4A90D9` | 半透明蓝底 `#4A90D9@20%` |
| 非激活 | `#888888` (灰色) | `#888888` | 透明 |
| 按下 | `#3A7BD5` (深蓝) | `#3A7BD5` | 半透明蓝底 `#3A7BD5@30%` |

### 1.4 切换动画

- **动画类型**：LVGL `lv_scr_load_anim`
- **动画效果**：`LV_SCR_LOAD_ANIM_MOVE_LEFT` / `LV_SCR_LOAD_ANIM_MOVE_RIGHT`
- **动画时长**：250ms
- **方向规则**：目标屏幕编号 > 当前屏幕 → 向左滑入；反之向右滑入

```c
/* 示例代码 */
lv_scr_load_anim(target_screen,
    (target_idx > current_idx) ? LV_SCR_LOAD_ANIM_MOVE_LEFT
                               : LV_SCR_LOAD_ANIM_MOVE_RIGHT,
    250, 0, false);
```

### 1.5 导航栏实现要点

- 导航栏在每个屏幕上**独立创建**（LVGL 屏幕切换时旧屏幕的控件不可见）
- 使用 `lv_obj_align(nav_bar, LV_ALIGN_BOTTOM_MID, 0, -20)` 定位
- 按钮使用 `lv_btn` + `lv_label`，事件回调中调用 `lv_scr_load_anim`
- 当前激活按钮的 `LV_STATE_CHECKED` 通过 `lv_obj_add_state(btn, LV_STATE_CHECKED)` 设置

## 2. 设备卡片组件规范

### 2.1 卡片网格布局

设备控制面板采用 **2 列自适应网格** 布局：

面板页是产品主屏，不是聊天入口页。推荐结构为：

```text
Smart Home                         Ready

Living Room
  [ Light       ON       65% ]

Bedroom
  [ Light       OFF          ]
  [ AC          ON       25C ]

Temp 25C       Hum 62%       Light 500lx

Panel              Chat              Settings
```

设计要点：

- 设备状态优先于对话入口，用户打开应用首先看到家居状态。
- 设备多时按房间分组；设备少时可保持 2 列卡片，但仍应显示房间语义。
- 顶部保留 Agent 状态短文本：`Ready` / `Thinking` / `Tool running` / `Network error`。
- 卡片表达设备状态，不承载长说明；复杂操作进入控制弹窗。
- 浅色背景下通过边框、状态点、轻阴影建立层级，不使用深色块制造压迫感。

```
┌─────────────────────────────────────┐
│ Smart Home                    Ready │  ← 标题栏 (h=40px)
├─────────────────────────────────────┤
│ Living Room                         │
│  ┌───────────────┐                  │
│  │ LIGHT         │                  │
│  │ Living Light  │                  │
│  │ ON  Level 65% │                  │
│  └───────────────┘                  │
│ Bedroom                             │
│  ┌────────┐ ┌────────┐              │
│  │ LIGHT  │ │ AC     │              │
│  │ OFF    │ │ ON 25C │              │
│  └────────┘ └────────┘              │
├─────────────────────────────────────┤
│ Temp 25C   Hum 62%   Light 500lx   │  ← 传感器条 (h=32px)
├─────────────────────────────────────┤
│ [Panel]       [Chat]       [Setting]│  ← 导航栏
└─────────────────────────────────────┘
```

**卡片尺寸规范**：

| 属性 | 值 | 说明 |
|------|-----|------|
| 卡片宽度 | `(屏幕宽 - 3×间距) / 2` ≈ 196px | 2 列等宽 |
| 卡片最小高度 | 100px | |
| 卡片圆角 | 12px | `lv_obj_set_style_radius(card, 12, 0)` |
| 卡片间距 | 10px | 水平 + 垂直 |
| 卡片内边距 | 12px | 四边 |
| 网格容器上边距 | 50px | 标题栏下方 |
| 网格容器下边距 | 88px | 传感器条 + 导航栏 |

### 2.3 设备类型图标映射

| 设备类型 | 图标字符 | Unicode | ON 颜色 | 参数 |
|---------|---------|---------|---------|------|
| light (灯) | 💡 | `\xF0\x9F\x92\xA1` | `#FFD700` 金色 | 亮度 (0-100%) |
| ac (空调) | ❄️ | `\xE2\x9D\x84` | `#4CD964` 绿色 | 温度 (16-30°C) |
| fan (风扇) | 🌀 | `\xF0\x9F\x8C\x80` | `#5AC8FA` 蓝色 | 档位 (1-3) |

> **注意**：Emoji 图标依赖 MiSans 字体支持。若 MiSans 不包含对应 Emoji，改用 LVGL 内置 Symbol 或纯文字替代方案：
> - light → `LV_SYMBOL_IMAGE` 或 "灯"
> - ac → `LV_SYMBOL_LOOP` 或 "空调"
> - fan → `LV_SYMBOL_REFRESH` 或 "风扇"

### 2.5 卡片交互流程

```
用户点击卡片
    │
    ▼
显示控制弹窗 (overlay)
    │
    ├─ 拖动滑块 → 实时更新参数显示值（不提交）
    ├─ 点击开关 → 切换 ON/OFF 状态（不提交）
    │
    ├─ 点击「确认」
    │   ├─ 显示加载状态（卡片 + 弹窗同时）
    │   ├─ 调用 device_state_set() 更新内存状态
    │   ├─ 调用 lvgl_ui_device_update() 刷新卡片
    │   ├─ 关闭弹窗
    │   └─ 显示成功/失败 toast 提示
    │
    ├─ 点击「取消」
    │   └─ 关闭弹窗，不修改任何状态
    │
    └─ 点击「返回」
        └─ 关闭弹窗，不修改任何状态
```

### 2.6 状态更新实时反馈

- 设备状态变更后，卡片背景色、图标、状态文字在 **100ms 内** 完成过渡
- 使用 `lv_obj_set_style_bg_color` + `LV_ANIM_ON` 实现颜色渐变
- Agent 通过工具调用变更设备时，同样触发 UI 刷新（通过 `lvgl_ui_device_update` 回调）

### 2.7 房间过滤

当设备数量较多时（如 8 个房间 × 3 种设备 = 24 个），面板卡片网格会变得拥挤。提供**按房间过滤**的下拉选择器：

```
┌─────────────────────────────────────┐
│           🏠 智能家居           [▼ 全部房间]│  ← 标题栏 + 房间选择器
├─────────────────────────────────────┤
│  ┌──────────┐  ┌──────────┐        │
│  │  💡       │  │  ❄️       │        │
│  │  客厅灯   │  │  客厅空调  │        │  ← 仅显示"客厅"的设备
│  │  ● ON    │  │  ○ OFF   │        │
│  └──────────┘  └──────────┘        │
```

**房间选择器规范**：

| 属性 | 值 | 说明 |
|------|-----|------|
| 位置 | 标题栏右侧 | `lv_obj_align(dropdown, LV_ALIGN_RIGHT_MID, 0, 0)` |
| 宽度 | 100px | 显示 "全部房间 ▼" |
| 默认值 | "全部房间" | 显示所有设备 |
| 下拉项 | 全部房间 + 已存在的房间列表 | 动态生成（从 `g_devices` 遍历房间名） |
| LVGL 控件 | `lv_dropdown` | `lv_dropdown_set_options(dd, "全部房间\n客厅\n卧室\n书房")` |

**过滤规则**：

| 规则 | 说明 |
|------|------|
| 选择"全部房间" | 网格显示所有已注册设备，2 列等宽 |
| 选择特定房间 | 仅显示该房间的设备，同时显示该房间的传感器数据 |
| 房间不存在设备 | 下拉项中不显示空的房间（从 `g_devices` 动态收集） |
| 过滤切换 | 立即刷新网格，卡片重新排列，无动画（避免所有卡片同时动画的抖动） |

**实现要点**：

```c
/* 房间过滤回调 */
static void on_room_filter_changed(lv_event_t *e) {
    lv_obj_t *dd = lv_event_get_target(e);
    char selected[32];
    lv_dropdown_get_selected_str(dd, selected, sizeof(selected));

    /* 重建卡片网格 */
    rebuild_device_grid(strcmp(selected, "全部房间") == 0 ? NULL : selected);
}

/* 从 g_devices 动态收集房间列表 */
static void rebuild_room_filter_options(lv_obj_t *dd) {
    char options[256] = "全部房间";
    /* 遍历 g_devices，收集不重复的房间名 */
    for (int i = 0; i < g_device_count; i++) {
        if (room_not_in_options(options, g_devices[i].room)) {
            strlcat(options, "\n", sizeof(options));
            strlcat(options, room_display_name(g_devices[i].room), sizeof(options));
        }
    }
    lv_dropdown_set_options(dd, options);
}
```

## 3. 工具调用卡片设计规范

### 3.1 嵌入位置

工具调用卡片**无缝嵌入聊天信息流**中，位于用户消息气泡与 Agent 回复气泡之间：

```
  ┌────────────────────────┐
  │  User: Turn on light     │  ← 用户气泡 (右对齐, 浅蓝底)
  └────────────────────────┘
  ┌────────────────────────┐
  │  🔧 control_device     │  ← 工具调用卡片 (左对齐, 橙色边框)
  │  ├ device: light       │
  │  ├ room: living_room   │
  │  └ result: ✅ ok       │
  └────────────────────────┘
  ┌────────────────────────┐
  │  Assistant: Done         │  ← Agent 气泡 (左对齐, 白色卡片)
  └────────────────────────┘
```

### 3.2 卡片视觉规范

工具调用卡片与聊天气泡的**视觉区分**：

| 属性 | 聊天气泡 | 工具调用卡片 |
|------|---------|-------------|
| 对齐 | 右(用户) / 左(Agent) | 左对齐 |
| 背景色 | `#E8F1FE`(用户) / `#FFFFFF`(Agent) | `#FFF8EA` 浅琥珀 |
| 边框 | 1px `#DCE3EC` | 左侧 3px `#D98A14` |
| 圆角 | 14px | 8px |
| 宽度 | 85% | 80% |
| 图标 | 无 | 🔧 工具图标 |

### 3.3 卡片内容结构

```
┌────────────────────────────────────┐
│ 🔧 control_device          ✅ 成功 │  ← 标题行：工具名 + 状态
├────────────────────────────────────┤
│  device: light                     │  ← 参数区
│  room: living_room                 │
│  action: on                        │
├────────────────────────────────────┤
│  result: {"ok":true,"state":"on"}  │  ← 结果区（可折叠）
│                          [详情 ▼]  │  ← 展开/折叠按钮
└────────────────────────────────────┘
```

**卡片高度自适应规则**：

| 状态 | 高度 | 说明 |
|------|------|------|
| 加载中 | 48px | 仅显示标题行 + 旋转指示器 |
| 成功（折叠） | 72px | 标题行 + 1行参数摘要 |
| 成功（展开） | 自适应，最大 60% 屏幕高 | 标题行 + 全部参数 + 结果 |
| 失败 | 72px | 标题行 + 错误信息 + 重试按钮 |

### 3.4 调用状态指示

| 状态 | 图标 | 颜色 | 说明 |
|------|------|------|------|
| 加载中 | ◌ (旋转) | `#FF9500` 橙色 | 工具正在执行 |
| 成功 | ✅ | `#4CD964` 绿色 | 执行成功 |
| 失败 | ❌ | `#FF3B30` 红色 | 执行失败 |

**加载动画**：使用 `lv_spinner` 控件，尺寸 16×16px，旋转周期 800ms。

### 3.5 操作按钮

| 按钮 | 显示条件 | 功能 |
|------|---------|------|
| 重试 | 失败状态 | 重新执行该工具调用 |
| 详情 ▼/▲ | 成功状态 | 展开/折叠结果 JSON |
| 复制 | 展开状态 | 将结果复制到剪贴板（可选） |

### 3.6 工具调用卡片数据流

```
agent_loop.c: tool_exec_thread()
    │
    ├─ 工具执行前:
    │   smart_home_lvgl_event_cb(AGENT_EVENT_TOOL_CALL)
    │   → 在聊天流中插入「加载中」卡片

    │   smart_home_lvgl_event_cb(AGENT_EVENT_TOOL_RESULT)
```

### 3.7 语音输入 (PTT) 交互

对话界面底部提供**按住说话 (Push-to-Talk)** 入口，与文本输入框共存：

```
┌─────────────────────────────────────────┐
│  ... 对话气泡 + 工具卡片区域 (可滚动) ...  │
├─────────────────────────────────────────┤
│  ┌──────────────────────────────┐ [🎤]  │  ← 输入框 + PTT 按钮
│  │  输入消息...                   │       │
│  └──────────────────────────────┘       │
└─────────────────────────────────────────┘
```

**PTT 按钮规范**：

| 属性 | 值 | 说明 |
|------|-----|------|
| 位置 | 输入框右侧 | 紧跟文本输入框 |
| 尺寸 | 44×44px | 触控友好 |
| 图标 | 麦克风 PNG / `LV_SYMBOL_AUDIO` | 图标缺失时显示文字 "Voice" |
| 背景 | 空闲: `#E8F1FE` / 录音中: `#FFE8E6` | 浅色底 + 红色状态点提示录音 |
| 圆角 | 22px (圆形) | 圆形按钮 |

**PTT 交互状态机**：

```
空闲 (🎤 灰色圆形按钮)
  │
  │ 用户按下 (touch down)
  ▼
录音中 (🔴 红色圆形按钮 + 脉冲动画)
  │
  ├─ 用户松开 (touch up) → 停止录音 → 发送 ASR 识别
  │     │
  │     ├─ ASR 成功 → 文本填入输入框 → 自动发送
  │     └─ ASR 失败 → 红色 toast "语音识别失败，请重试" → 回空闲
  │
  ├─ 录音超时 (60s) → 自动停止 → 发送 ASR
  │
  └─ 用户上滑 (swipe up) → 取消录音 → 回空闲
```

**录音状态视觉反馈**：

| 元素 | 空闲 | 录音中 |
|------|------|--------|
| PTT 按钮背景 | `#E8F1FE` | `#FFE8E6` + 红色状态点 + 轻脉冲 |
| 提示文字 | "按住说话" | 显示实时录音时长 "00:12" |
| 波形指示器 | 无 | 音量条（根据 PCM 幅度跳动的竖条） |

**PTT 按钮触摸事件**：

```c
/* PTT 按钮事件处理 */
static lv_obj_t *ptt_btn;

static void ptt_pressed_cb(lv_event_t *e) {
    /* 开始录音 */
    audio_capture_start();
    lv_obj_set_style_bg_color(ptt_btn, lv_palette_main(LV_PALETTE_RED), 0);
    lv_label_set_text(ptt_btn_label, LV_SYMBOL_AUDIO);  /* 或 "🔴" */
    show_recording_wave();   /* 显示波形指示器 */
}

static void ptt_released_cb(lv_event_t *e) {
    /* 停止录音，发送 ASR */
    audio_capture_stop();
    lv_obj_set_style_bg_color(ptt_btn, lv_color_hex(0x3A3A55), 0);
    lv_label_set_text(ptt_btn_label, "🎤");
    hide_recording_wave();

    /* 将 PCM 数据发送给 ASR 服务 */
    asr_submit(audio_buffer, audio_len, on_asr_result, NULL);
}
```

**文本输入回退**：PTT 是输入增强，不是替代。当用户不想说话（安静环境、隐私考虑）时，文本输入框始终可用。交互规则：

| 场景 | 行为 |
|------|------|
| PTT 识别文本返回 | 自动填入输入框 → 立即发送消息 |
| 用户正在文本输入 | 切换回文本模式，PTT 仅在按下时激活 |
| 录音中用户开始打字 | 自动取消录音 → 切换到文本输入 |
| 无音频设备 | PTT 按钮隐藏，文本输入占满整行 |

**线程安全**：音频采集在独立线程中运行（`audio_capture` 模块），ASR 回调通过 `lv_async_call` 投递到 LVGL 线程更新 UI。不可在 ASR 回调中直接操作 LVGL 控件。

### 5.3 响应式适配

虽然当前目标为 466×466 圆形屏，UI 代码应使用相对布局以适配不同尺寸：

| 规则 | 实现方式 |
|------|---------|
| 宽度自适应 | `lv_pct(85)`、`lv_pct(100)` 代替固定像素 |
| 高度内容自适应 | `LV_SIZE_CONTENT` |
| 安全区域避让 | 圆形屏四角 padding：上 60px、下 76px（导航栏）、左右 50px |
| 字体缩放 | 通过 `smart_home_lvgl_style.c` 统一调整字号 |

**圆形屏安全区域计算**：

```
在 y 距离屏幕顶部 h 处，水平可视宽度为：
  visible_width = 2 × sqrt(R² - (R - h)²)
  其中 R = 233 (屏幕半径)

示例：
  h=60  → visible_width ≈ 410px
  h=100 → visible_width ≈ 430px
  h=200 → visible_width ≈ 460px (接近满宽)
```

### 5.4 错误处理

| 错误场景 | 处理方式 |
|---------|---------|
| 设备创建失败 | 弹出红色 toast："创建失败，请重试" |
| 设备控制失败 | 卡片恢复原状态 + 红色 toast |
| Agent 无响应 | 聊天界面显示超时提示气泡 |
| Agent 推理超时 | 聊天界面显示超时气泡 + "重试"按钮，参见 [5.4.1](#541-agent-超时反馈) |
| Agent 网络错误 | 聊天界面显示网络错误气泡 + "重试"按钮 |
| Agent 返回错误 | 聊天界面显示错误气泡，含错误码和简要说明 |
| LVGL 控件创建失败 | `syslog` 记录错误，不崩溃 |
| 内存不足 | `mallinfo()` 检测，拒绝创建新控件 |

#### 5.4.1 Agent 超时反馈

当 Agent 推理超时或网络错误时，在聊天信息流中插入**系统提示气泡**，与普通聊天气泡视觉区分：

```
  ┌────────────────────────┐
  │  用户: 打开客厅的灯      │  ← 用户气泡 (右对齐)
  └────────────────────────┘
  ┌────────────────────────┐
  │  ⚠ Agent 暂时无响应     │  ← 超时提示气泡 (居中, 黄色)
  │  请检查网络连接后重试    │
  │            [重试]       │  ← 重试按钮
  └────────────────────────┘
```

**超时气泡规范**：

| 属性 | 值 | 说明 |
|------|-----|------|
| 对齐 | 居中 | 与用户/Agent 气泡区分 |
| 背景色 | `#FFF6E5` 浅黄底 | 局部警告，不使用深色警告块 |
| 边框 | 左侧 3px `#FF9500` 橙色 | 与工具调用卡片一致 |
| 图标 | ⚠ `LV_SYMBOL_WARNING` | 16px，橙色 |
| 文字大小 | 12px | 辅助文字 |
| 圆角 | 8px | |
| 宽度 | 80% | |

**超时触发条件与 UI 映射**：

| Agent 错误码 | 含义 | 气泡文字 | 按钮 |
|-------------|------|---------|------|
| `AGENT_ERROR_TIMEOUT` (-6) | 整体/模型/工具超时 | "Agent 响应超时" | [重试] |
| `AGENT_ERROR_NETWORK` (-10) | 网络传输失败 | "网络连接失败，请检查网络" | [重试] |
| `AGENT_ERROR_CANCELLED` (-7) | 被取消 | "已取消" | 无（自动消失 2s） |
| `AGENT_ERROR_MODEL` (-9) | 模型返回错误 | "AI 服务暂时不可用" | [重试] |
| `AGENT_ERROR_LIMIT` (-5) | 迭代/缓冲区溢出 | "回复内容过长" | 无 |

**重试按钮行为**：

```c
static void on_retry_click(lv_event_t *e) {
    /* 重新发送上一条用户消息 */
    const char *last_input = chat_get_last_user_message();
    if (last_input) {
        /* 移除超时气泡 */
        lv_obj_del(timeout_bubble);
        /* 重新提交到 Agent */
        agent_chat_async(last_input);
    }
}
```

**超时检测实现**：通过 `agent_event_cb_t` 监听 `AGENT_EVENT_ERROR` / `AGENT_EVENT_TIMEOUT` / `AGENT_EVENT_CANCELLED` 事件。回调中通过 `lv_async_call` 投递到 LVGL 线程创建/更新超时气泡：

```c
static void demo_event_cb(const agent_event_t *event, void *user_data) {
    switch (event->type) {
    case AGENT_EVENT_TIMEOUT:
    case AGENT_EVENT_ERROR:
    case AGENT_EVENT_CANCELLED: {
        timeout_bubble_data_t *p = malloc(sizeof(*p));
        p->error_code = event->error_code;
        strncpy(p->message, event->message, sizeof(p->message) - 1);
        lv_async_call(show_timeout_bubble_cb, p);
        break;
    }
    case AGENT_EVENT_MODEL_REQUEST:
        /* 显示 "正在思考..." 指示器 */
        lv_async_call(show_thinking_indicator_cb, NULL);
        break;
    case AGENT_EVENT_MODEL_RESPONSE:
    case AGENT_EVENT_RUN_DONE:
        /* 隐藏 "正在思考..." */
        lv_async_call(hide_thinking_indicator_cb, NULL);
        break;
    default:
        break;
    }
}
```

### 8.1 平台约束

| 约束 | 值 | 影响 |
|------|-----|------|
| 屏幕分辨率 | 466×466 | 圆形屏，四角裁切 |
| 色深 | RGB565 (16bit) | 最多 65536 色，渐变可能有条纹 |

| DPI | 130 | 图标和文字需足够大 |
| CJK 字体 | MiSans-Normal (FreeType) | 需运行时创建，必须在 LVGL 线程 |
| 堆内存 | ~2MB 可用 | 控件数量需限制 |

字体加载路径由 `CONFIG_SMART_HOME_DEMO_DATA_ROOT` 控制，默认：

```text
/data/res/fonts/MiSans-Normal.ttf
```

代码通过 `smart_home_lvgl_style_init()` 创建 12/14/16/20 四档字体。
若 FreeType 或字体文件不可用，回退到 LVGL Montserrat，英文仍可显示，但中文不完整。

PNG 图标从 `CONFIG_SMART_HOME_DEMO_UI_LVGL_ICONS` 指定目录加载，默认
`/data/res/icons`。源码 PNG 位于 `packages/demos/smart_home/res/icons/`，
需要通过 ROMFS 或 data partition 部署到目标路径。LVGL 配置需启用
`LV_USE_LIBPNG` 或 `LV_USE_LODEPNG`。

### 8.2 LVGL 线程安全规则

1. **所有 LVGL 控件操作必须在 LVGL 线程中执行**
2. 外部线程（Agent loop、工具执行线程）通过 `lv_async_call()` 调度 UI 更新
3. `lv_async_call` 的回调中可安全创建/修改/删除控件
4. 回调中分配的 payload 必须在回调结束时 `free`
5. **`agent_event_cb_t` 回调在 Agent 推理线程中同步执行**，不可直接操作 LVGL 控件。需更新 UI 时，必须在回调中 `malloc` 数据并通过 `lv_async_call` 投递到 LVGL 线程
6. 音频采集线程、网络管理线程等同样适用规则 2

```c
/* 正确：从 Agent 线程更新 UI */
typedef struct {
    char device[32];
    int state;
} device_update_t;

static void device_update_async_cb(void* data) {
    device_update_t* p = (device_update_t*)data;
    /* 安全地更新 LVGL 控件 */
    update_device_card(p->device, p->state);
    free(p);  /* 必须释放 */
}

void lvgl_ui_device_update(const char* device, int state) {
    device_update_t* p = malloc(sizeof(device_update_t));
    if (!p) return;
    strncpy(p->device, device, sizeof(p->device) - 1);
    p->state = state;
    lv_async_call(device_update_async_cb, p);
}
```

### 8.5 Kconfig 配置

启用 LVGL UI 需要在 menuconfig 中设置：

```
Application Configuration → Packages → [*] Vela AI Agent
    → [*] Smart home demo
        → Smart home UI backend
            → [*] LVGL UI  (CONFIG_SMART_HOME_DEMO_UI_LVGL=y)
```

依赖关系：
- `CONFIG_GRAPHICS_LVGL=y` (已启用)
- `CONFIG_LV_USE_FREETYPE=y`，用于可选 MiSans 字体加载
- `CONFIG_SMART_HOME_DEMO_DATA_ROOT="/data"`，用于定位字体资源
- `CONFIG_LV_USE_LIBPNG=y` 或 `CONFIG_LV_USE_LODEPNG=y`，用于 PNG 图标
- `CONFIG_SMART_HOME_DEMO_UI_LVGL_ICONS="/data/res/icons"`，用于定位 PNG 图标
