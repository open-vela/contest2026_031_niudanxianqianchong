# 房间管理与设备分配验收

## 入口与行为

- 首页房间栏读取本地目录并补入可见网关设备的房间；横向滚动显示，选择后仅显示该房间设备。删除当前选中的房间后回到“全部”。
- 房间栏右侧 `＋` 打开房间管理弹窗，支持新增、删除和重新保存。
- 新增最多 6 个本地房间；名称必须是有效 UTF-8，不超过 23 字节，支持中文以及英文字母、数字、下划线、连字符。拒绝空名、重名和非法字符。
- 新增页提供书房、阳台、厨房、餐厅、儿童房、客房、客厅、卧室等中文预设；屏幕键盘用于自定义英文/数字名称。中文输入法尚未接入。
- 删除前选择迁移目标并二次确认；本地设备、已保存的米家分组以及当前已发现的同房间米家设备一起迁移。无有效目标时不可删除，至少保留一个本地房间。
- 本地灯、空调和米家设备的控制弹窗中可点“分配房间”。本地设备按稳定 ID 调整；米家设备以 `milo:<did>` 保存本屏覆盖，**不修改米家云端房间**。
- 米家分组覆盖最多 16 条。未发现且尚未建立覆盖的新设备仍沿用网关房间。
- 当前首页仍按原能力支持灯、空调、洗衣机、扫地机器人、摄像头、风扇六类卡片，最多 12 张；本次不扩展设备驱动或网关设备类别。
- 有真实目录但没有设备时显示空列表，不回退到演示设备；有真实设备时显示对应的数据来源。

## 数据与资源

`state.json` 保持 version 1，扩展可选 `room_bindings` 数组；旧文档没有该字段也可加载。
房间目录、本地设备所属房间和网关设备覆盖一起保存。删除迁移使用临时副本，全部校验成功后才提交，失败不会留下部分迁移。
修正了本地灯的非连续稳定 ID 在反序列化中不能正确恢复的问题。

启动时加载已保存状态；业务校验失败时保留完整默认状态。房间修改先更新内存，再由后台线程写入完整状态快照。
界面显示“保存中 / 已保存 / 本次已生效，保存失败”，失败可在管理页重试；保存期间拒绝新的房间修改。
后台线程只持有独立状态副本，不持有页面或 app 指针，关闭页面不会等待文件 I/O，也不会回调已销毁的控件。
断电或退出发生在保存完成前时，不承诺本次修改已落盘；每次设备控制状态的即时持久化也不属于本功能。

- `smart_home_state_t` 由约 756 字节增至 2020 字节（当前 32 位/主机 ABI 的本结构布局），新增空间主要是 16 条稳定键房间覆盖。
- 保存任务额外使用一个状态副本及 32 KiB 线程栈，任务退出后释放。
- 删除房间时临时快照整个网关设备列表，放在 bulk 堆，不放在线程栈上；完成匹配后立即释放。
- 未增加 PNG、动画或字体资源；复用现有 MiSans 和图标。新增下拉框、文本输入与预设中文名称使用 MiSans。
